# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal site published to GitHub Pages, built with [mdBook](https://rust-lang.github.io/mdBook/) (a Rust static-site generator). Content is Markdown; there is no application code.

The site is **bilingual**, and Korean and English are **two separate mdBook projects in this one repository** — not one book with language sections. Keeping them separate is what gives each language its own sidebar, chapter numbering, search index, and `<html lang>`.

## Commands

```bash
mdbook build ko      # → book/ko
mdbook build en      # → book/en
mdbook serve ko      # live-reload dev server for one language
```

There is no top-level book: `mdbook build` at the repository root does nothing useful. Always name the language directory.

To reproduce a deploy locally:

```bash
mdbook build ko && mdbook build en
cp index.html book/
python3 scripts/gen_sitemap.py
```

`mdbook` is a Rust binary; install with `cargo install mdbook` if missing. Deploys pin **mdBook v0.4.40** (see `.github/workflows/deploy.yml`), so prefer that version when reproducing build behavior. Note that v0.4.40 has no `aarch64-apple-darwin` release — on Apple Silicon, use the `x86_64-apple-darwin` build under Rosetta.

There are no tests or linters.

## Architecture

```
ko/book.toml   ko/src/   ko/theme/     Korean book   → book/ko
en/book.toml   en/src/   en/theme/     English book  → book/en
index.html                             language selection landing page
scripts/gen_sitemap.py                 sitemap.xml + robots.txt
drafts/                                unpublished manuscripts (see below)
```

- **`<lang>/src/SUMMARY.md`** is the table of contents **and** the router. mdBook only renders pages linked from it; a new `.md` under `src/` is invisible until it is listed there.
- **Slugs are identical across languages.** `ko/src/x.md` and `en/src/x.md` produce `/ko/x.html` and `/en/x.html`. This symmetry is load-bearing — the language switcher and the sitemap's hreflang both depend on it. When adding a page in one language, use the same filename in the other, even though the title differs.
- **`<lang>/theme/head.hbs`** injects the language switcher. It is deliberately *not* in `SUMMARY.md`: a link there makes mdBook treat it as a chapter and auto-create stray source files (`ko/en/index.html`).
- **`index.html`** is copied into `book/` by the workflow, not generated by mdBook.

### Language selection

`index.html` offers a choice; it does **not** auto-redirect by browser language. Google advises against that — automatic redirection "could prevent users (and search engines) from viewing all the versions of your site." Do not add one.

### hreflang

`scripts/gen_sitemap.py` walks the built output and writes `book/sitemap.xml` with reciprocal hreflang annotations, **only for pages that exist in both languages**. A one-way annotation is ignored by Google, so a Korean post without an English counterpart must not claim one. The script handles this; do not hand-edit the sitemap.

hreflang is not emitted into `<head>` because mdBook's `{{ path }}` yields the source path with a `.md` extension and Handlebars has no string replacement. Sitemap-level hreflang is equally supported.

## Drafts and the publishing flow

`drafts/` holds unpublished manuscripts. It sits outside every book's `src/`, so mdBook never builds it — but **it is visible in this public repository**. See `drafts/README.md`, which warns readers not to follow unverified drafts.

**Korean is the source of truth.** Write and revise the Korean manuscript first; write the English version only once the Korean text has settled. Otherwise every review finding has to be fixed twice. This ordering is the reason the repository tolerates having the same content in two places at all.

**Publishing is a move, not a copy** — `drafts/<series>/<post>.md` → `<lang>/src/<series>/<post>.md`. Exactly one copy exists at any moment. Each series has a `_PUBLISH.md` tracker holding the per-post steps, the prepared `SUMMARY.md` line, and the checklist state. Follow the series' own tracker rather than improvising, and publish in reading order — posts link to their "next" installment, which 404s until that one is published.

**Never publish without being asked.** Moving a draft into `<lang>/src/` and pushing to `main` puts it on the live site. Treat publishing as a separate, explicitly requested action.

### Evidence labels

Technical posts tag each claim with its provenance: `[관찰]` (ran it — shown output is real output), `[문서]` (verbatim vendor quote), `[추론]` (inferred, not directly verified). Each post ends with a **"확인 못 한 것"** section listing what could not be confirmed.

These exist because an earlier season shipped fabricated citations — quoted sentences that existed nowhere. So:

- A `[문서]` quote must be verbatim and contiguous, with every elision marked.
- A `[관찰]` claim means the command was actually run; paste real output, not a paraphrase of it.
- Never add a label to satisfy the convention. Backporting labels to an existing post means re-verifying its claims first.
- Before writing "확인 못 했습니다", check whether the answer is in a source already cited, or readable from an installed package's source. It often is.

## Adding a page

1. Create the Markdown file under `ko/src/` **and** `en/src/`, using the **same filename** in both.
2. Add a link under the matching `SUMMARY.md` — otherwise it will not appear.
3. Build both books and confirm the sidebar, navigation, and sitemap pairing.

## Commit messages

Write commit messages that describe only the change itself. Do not mention Claude, Claude Code, or any AI assistance — no `Co-Authored-By: Claude` trailer, no "Generated with Claude Code" line, no references in the subject or body.

## Deployment

Pushing to `main` triggers `.github/workflows/deploy.yml`, which builds both books, copies the root pages, generates the sitemap, and publishes `book/` to GitHub Pages. There is no manual deploy step.

The repository must stay **public**: GitHub Pages is available from private repositories only on GitHub Pro or higher.
