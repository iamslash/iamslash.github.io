# 8편. 훔쳐보기의 함정 — peeking과 sequential testing

> 시리즈: 밑바닥부터 이해하는 A/B 테스트 통계
> 이 편에서 배우는 것: 실험 도중 자꾸 결과를 들여다보면 왜 가짜 승자가 폭증하는지, 그리고 그래도 매일 보고 싶다면 어떻게 해야 하는지.

7편에서 우리는 콩마켓 실험을 아주 성실하게 설계했습니다. "상대 +12% 차이를 80% 검정력으로 잡으려면 arm당 22,000명, 약 2주가 필요하다"고 미리 계산해 뒀죠. 그런데 실전에서는 이런 유혹이 찾아옵니다.

실험을 켠 지 3일째. 대시보드를 보니 초록 버튼(B)이 앞서고 있고 p-value가 0.04입니다. "오, 유의하네? 22,000명까지 기다릴 필요 있나? 지금 멈추고 초록 버튼으로 확정하자!"

이 한 번의 클릭이 바로 이 편의 주제인 **훔쳐보기(peeking)** 입니다. 그리고 이건 A/B 테스트에서 가장 흔하고 가장 비싼 실수 중 하나입니다.

## 훔쳐보기(peeking)란 무엇인가

**훔쳐보기(peeking)** — 실험이 끝나기 전에 중간 결과를 들여다보고, "유의하게 나온 순간" 실험을 멈춰 버리는 행동입니다.

말로만 들으면 합리적으로 느껴집니다. "빨리 결론 났는데 왜 계속 기다려? 리소스 낭비잖아." 하지만 통계적으로는 규칙 위반입니다. 왜냐하면 4편·5편에서 배운 p-value와 유의수준 5%라는 약속은 **"딱 한 번, 정해진 표본 크기에서 본다"** 는 전제 위에 세워진 것이기 때문입니다.

한 번 볼 때의 약속은 이랬습니다: "차이가 진짜 없어도, 우연히 p<0.05가 뜰 확률은 5%다." 5편에서 이걸 1종 오류(Type I error), 즉 헛발질 확률이라고 불렀죠. 문제는 이 5%가 **"한 번 볼 때"** 의 숫자라는 겁니다.

## 왜 여러 번 보면 위험한가 — 저격수의 과녁

비유를 하나 들겠습니다. 눈을 감고 벽에 화살을 마구 쏜 다음, 화살이 가장 촘촘히 박힌 자리에 나중에 과녁을 그리는 저격수를 상상해 보세요. 이 사람은 "명중률 100%"라고 자랑하겠지만, 사실은 아무것도 맞힌 게 아닙니다. 결과를 보고 나서 기준을 정한 것뿐이죠. (이걸 텍사스 명사수의 오류라고 부릅니다.)

훔쳐보기가 정확히 이 짓입니다. 매일 대시보드를 보다가 **"유의가 뜬 바로 그날"** 을 골라 멈추는 건, 화살이 몰린 자리에 과녁을 그리는 것과 같습니다.

숫자로 보죠. 하루 볼 때마다 우연히 유의할 확률이 5%라면:

- 1번 보면 헛발질 확률 5%
- 14번 보면서 "한 번이라도 유의하면 멈춘다"면, 헛발질 기회가 14번 생깁니다.

만약 14번 관측이 서로 완전히 독립이면 "14번 다 헛발질 안 할 확률"은 0.95를 14번 곱한 값(약 49%)이고, 나머지 51%가 헛발질 확률입니다. 하지만 실제로는 누적 데이터라 어제·오늘 값이 겹쳐 이 계산이 그대로 맞진 않습니다 — 다만 "볼수록 헛발질이 는다"는 방향은 같습니다. **볼 때마다 헛발질 기회가 한 번씩 추가되고, 그게 누적되어 실제 false positive는 5%를 훌쩍 넘습니다.** 얼마나 넘는지는 말이 아니라 코드로 직접 확인하는 게 제일 확실합니다.

## 콩마켓 시뮬레이션 — A/A 실험을 훔쳐보기

가장 공정한 실험 조건을 만들어 보겠습니다. 바로 **A/A 실험**입니다. 파란 버튼과 "또 다른 파란 버튼"을 비교하는 거죠. 두 버튼의 진짜 전환율은 **둘 다 정확히 5.0%**, 즉 차이가 **전혀 없습니다**. 정직한 검정이라면 여기서 "유의하다(승자가 있다)"고 외칠 확률은 5%여야 합니다.

이 A/A 실험을 5,000번 반복하는데, 매번 "여러 번 훔쳐보다가 첫 유의에서 멈추기"를 하면 가짜 승자 비율이 얼마나 되는지 세어 봅시다. z-test는 6편에서 쓴 2-표본 비율 검정 그대로입니다.

```python
import numpy as np
from scipy import stats

rng = np.random.default_rng(20240815)

TRUE_RATE = 0.05      # A/A 실험: 두 버튼 모두 진짜 전환율 5.0%, 차이 '없음'
ALPHA = 0.05
N_SIM = 5000          # 실험을 5,000번 반복
TOTAL = 22000         # arm당 총 방문자 (7편 설계와 동일)
MIN_COUNT = 10        # 비율 z 근사를 믿을 수 있는 최소 기대 성공/실패 수

def two_prop_pvalue(x_a, n_a, x_b, n_b):
    """2-표본 비율 z-test의 양측 p-value (6편과 동일)."""
    p_pool = (x_a + x_b) / (n_a + n_b)
    se = np.sqrt(p_pool * (1 - p_pool) * (1/n_a + 1/n_b))
    if se == 0:
        return 1.0
    z = ((x_b/n_b) - (x_a/n_a)) / se
    return 2 * (1 - stats.norm.cdf(abs(z)))

def false_positive_rate(n_looks):
    """차이가 '없는' A/A 실험을 n_looks번 훔쳐보며 '첫 유의에서 멈추기'.
       한 번이라도 p<0.05가 뜨면 '가짜 승자'로 카운트."""
    # 누적 표본 경계: 마지막 look은 정확히 arm당 TOTAL 명이 되도록 균등 분할
    cum_ns = np.linspace(0, TOTAL, n_looks + 1, dtype=int)[1:]
    fake_wins = 0
    for _ in range(N_SIM):
        cum_a = cum_b = 0
        prev = 0
        for n in cum_ns:
            inc = n - prev            # 이번 look에서 새로 유입된 방문자
            prev = n
            cum_a += rng.binomial(inc, TRUE_RATE)
            cum_b += rng.binomial(inc, TRUE_RATE)
            # 기대 성공/실패가 최소치를 넘긴 look부터만 모니터링(z 근사 보호)
            if n * TRUE_RATE < MIN_COUNT or n * (1 - TRUE_RATE) < MIN_COUNT:
                continue
            if two_prop_pvalue(cum_a, n, cum_b, n) < ALPHA:
                fake_wins += 1
                break                 # 여기서 실험을 멈추고 "승자다!"라고 외침
    return fake_wins / N_SIM

print("훔쳐보기 횟수     가짜 '유의' 비율")
for looks, label in [(1, "1번(끝에 한 번만)"),
                     (14, "14번(매일)"),
                     (28, "28번(하루 2번)"),
                     (336, "336번(매시간)")]:
    print(f"{label:16s}  {false_positive_rate(looks):.1%}")
```

실제로 돌린 결과입니다.

| 훔쳐보기 방식 | 가짜 "유의" 비율 |
|---|---|
| 1번 (끝에 한 번만 본다) | **5.5%** |
| 14번 (매일 본다) | **21.7%** |
| 28번 (하루 2번 본다) | **28.6%** |
| 336번 (매시간 본다) | **41.7%** |

(네 방식 모두 최종적으로는 arm당 22,000명을 똑같이 채웁니다. 다만 336번처럼 아주 자주 보는 경우, 초반엔 arm당 인원이 너무 적어 기대 구매 건수가 몇 건밖에 안 되므로 비율 z 근사가 깨집니다. 그래서 위 코드는 기대 성공·실패 수가 최소치(10건)를 넘긴 look부터만 판정에 넣습니다.)

숫자가 무섭습니다. 차이가 **전혀 없는** 두 버튼인데도:

- 규칙대로 **끝에 딱 한 번만** 보면 헛발질은 약 5%. 우리가 약속한 그대로입니다.
- 그런데 **매일 한 번씩** 보면서 유의 뜰 때 멈추면 **21.7%**. 무려 4배 넘게 부풀었습니다.
- 실시간 대시보드를 켜 놓고 **더 자주** 들여다볼수록 30%를 넘어 40%에 육박합니다.

다시 강조합니다. 이 실험엔 **진짜 승자가 없습니다.** 그런데도 훔쳐보기만으로 다섯 번 중 한 번꼴로(자주 보면 다섯 번 중 두 번꼴로) "초록 버튼이 이겼다!"는 가짜 결론이 나옵니다. 이렇게 뽑힌 승자를 배포하면, 실제 매출은 하나도 안 늘고 "우리가 개선했다"는 착각만 남습니다.

## 왜 하필 이렇게 부풀까 — 출렁임을 캡처하는 것

직관을 조금 더 다져 보겠습니다. 3편에서 표본이 작을수록 신뢰구간이 넓다고 했죠. 실험 초반, 데이터가 적을 때는 두 버튼의 관측 전환율이 운에 따라 크게 출렁입니다. 어떤 날은 B가 우연히 앞서고, 어떤 날은 A가 앞섭니다.

이 출렁임 중에서 **가장 극단적으로 벌어진 순간**만 골라 "지금 멈춰!"라고 하는 게 훔쳐보기입니다. 파도가 계속 치는데, 파도가 가장 높이 솟은 순간을 사진 찍어 "바다 높이가 이렇다"고 우기는 셈이죠. 오래 지켜볼수록 극단적인 순간을 만날 기회는 늘어나고, 그 순간을 캡처할 확률도 올라갑니다. 그래서 자주 볼수록 가짜 승자가 늘어나는 겁니다.

## 해결책 1 — 고전적 방법: 미리 정하고 끝까지 간다

가장 간단하고 확실한 해결책은 7편에서 이미 배웠습니다. **표본 크기를 미리 정하고, 그 숫자에 도달할 때까지 결과를 보지 않는 것**입니다.

콩마켓이라면 "arm당 22,000명이 모일 때까지는 대시보드의 유의 여부를 보지 않는다"고 규칙을 정하고, 딱 그때 딱 한 번 판단합니다. 위 표의 첫 줄(끝에 한 번만 → 5.5%)이 바로 이 방식이고, 약속한 5%를 지킵니다.

단점도 있습니다. 실험이 명백히 대박이거나 명백히 재앙이어도 정해진 기간을 다 채워야 하니, 답답하고 때로는 낭비처럼 느껴집니다. 그래서 "그래도 중간에 좀 보면서 빨리 끝내고 싶다"는 현실적 요구를 위한 두 번째 길이 있습니다.

## 해결책 2 — 순차검정(sequential testing): 매일 봐도 되게 문턱을 바꾼다

**순차검정(sequential testing)** — 실험 도중에 여러 번 들여다보는 것을 **허용하는** 방법입니다. 반복 관측을 계산에 미리 포함해, 언제 멈추더라도 전체 1종 오류(헛발질 확률)를 5%로 제어합니다. 방법에 따라 경계를 바꾸기도 하고, p-value나 증거 점수 자체를 순차 관측에 맞게 계산하기도 합니다.

핵심 아이디어는 이겁니다. 문제는 "여러 번 보는 것" 자체가 아니라, **여러 번 보면서 매번 똑같은 1.96(양측 α=0.05에 대응하는 z 임계값)이라는 헐거운 문턱을 쓴 것**이었습니다. 그러니 여러 번 볼 거라면 문턱을 그만큼 더 엄격하게 만들면 됩니다.

정리하면 이렇습니다. **여러 번 볼 계획이라면 처음부터 그 횟수를 감안한 계산법을 써야 합니다.** 끝에 한 번 볼 때 쓰던 문턱을 여러 번 그대로 재활용한 게 문제였으니, "여러 번 본다"는 사실 자체를 계산에 미리 넣은 방법으로 갈아타는 겁니다. 이런 계산법에는 몇 가지 갈래가 있는데, 이름이 낯설어도 목표는 하나로 같습니다 — 자주 봐도 전체 헛발질을 5%로 묶는 것.

> **용어 참고 — 순차검정 계열의 이름들.** 지금은 이름만 눈에 익혀 두면 충분합니다. 아래는 서로 다른 구현이지만 목표는 같습니다.
>
> - **알파 소비(alpha spending)** — 전체 예산 5%를 실험 기간에 걸쳐 조금씩 나눠 씁니다. 5%를 한 번에 다 쓰지 않고 여러 관측에 분배하는 거라, 매일 봐도 전체 헛발질은 5%를 넘지 않습니다(단, 사전에 정한 관측 시점 또는 information-time 규칙과 spending 함수를 따를 때). 예산을 어떻게 나눌지는 spending 함수가 정하는데, O'Brien–Fleming형은 초반 문턱을 매우 엄격하게 둡니다(초반엔 거의 안 멈추고 후반으로 갈수록 완화). 다만 이건 한 가지 설계 방식일 뿐, 모든 alpha-spending이 이런 모양은 아닙니다.
> - **언제 봐도 유효한 p-value(always-valid p-value)** — 실험 중 어느 시점에 멈춰서 봐도 5% 보장이 깨지지 않도록 설계된 p-value입니다. 대시보드를 언제 새로고침하든 그 값이 유효합니다.
> - **순차확률비검정(mSPRT 등)** — 위 아이디어를 구현하는 구체적 통계 기법으로, 매 관측마다 갱신되는 증거 점수를 정해진 경계와 비교해 "멈춤/계속"을 결정합니다.
> - **신뢰 순차구간(confidence sequence)** — 이름 그대로 순차 관측용 신뢰구간(매번 새로 계산해도 5% 약속이 안 깨지도록 만든 구간)입니다. 조정 파라미터 N\*로 "언제쯤 구간이 가장 좁아질지"를 맞춥니다. 뒤의 GrowthBook 설명에서 다시 나옵니다.

셋 다(또는 그 이상) 결론은 같습니다. **순차검정은 반복 관측을 계산에 미리 반영해서, 자주 봐도 전체 5% 약속이 지켜지게 만듭니다.** 경계를 바꾸든 p-value·증거 점수를 순차 관측에 맞게 다시 계산하든, 방식은 달라도 목표는 하나입니다.

여기서 오해하면 안 되는 게 있습니다. **순차검정이 고치는 것은 "같은 사전 지정 가설을 여러 시점에 보며 멈추는(optional-stopping) 오류" 딱 하나입니다.** 다중 지표를 동시에 본다든지, 지표·세그먼트를 결과를 본 뒤에 바꾼다든지, SRM(배정 비율이 틀어짐)이나 로깅 오류, 편향된 배정 같은 문제는 순차검정이 전혀 손대지 않습니다. 이런 것들은 각각 별도로 처리해야 합니다(다중비교·SRM 같은 주제는 다음 편에서 다룹니다).

공짜도 아닙니다. 순차검정으로 얻는 신뢰구간은 같은 시점의 고정표본 신뢰구간보다 넓습니다. 대신 효과가 강하면 조기에 멈춰서 평균적으로 표본을 아낄 수도 있고, 반대로 효과가 경계선에 걸쳐 애매하면 고정표본 설계보다 더 많은 표본이 필요할 수도 있습니다. "빨리 볼 수 있는 자유"의 대가로 상황에 따라 검정력이나 표본을 조금 더 쓰는 셈이죠.

## 프레임워크에서 어디에 쓰이나

실무용 A/B 프레임워크가 그냥 z-test만 돌린다면 사용자를 훔쳐보기 지옥으로 밀어 넣는 셈입니다. 그래서 성숙한 프레임워크는 순차검정을 옵션으로 제공합니다. 예를 들어 [GrowthBook](https://www.growthbook.io/)에는 **Sequential Testing** 옵션이 있는데, 이걸 켜면 신뢰구간과 유의 판정이 위에서 말한 "언제 봐도 유효한" 방식으로 계산되어, 대시보드를 매일 들여다봐도 결론을 신뢰할 수 있게 됩니다. 참고로 GrowthBook의 현재 구현은 alpha-spending 경계가 아니라 조정 파라미터(N\*)를 둔 **점근적 confidence sequence** 방식입니다([문서](https://docs.growthbook.io/statistics/sequential)). alpha spending은 같은 목표를 이루는 또 다른 구현일 뿐이고요. 우리가 프레임워크를 밑바닥부터 구현한다면, 결과 계산 모듈에 "고정 표본 모드(끝에 한 번)"와 "순차 모드(언제든 유효한 confidence sequence로 판정)"를 스위치로 두는 설계가 자연스럽습니다.

> **실물 참고(무료 vs 상용).** 단, GrowthBook에서 이 **Sequential Testing은 상용(Cloud의 Pro / 셀프호스트의 Enterprise) 기능**이라 무료 셀프호스트 버전에선 토글이 잠겨 있습니다. 그래도 위에서 봤듯 원리는 confidence sequence를 직접 구현하면 그대로 재현됩니다.

## 한 줄 정리

실험을 자주 훔쳐보고 "유의 뜨면 바로 멈추기"를 하면 헛발질 확률이 5%에서 20~40%로 폭증하니, 표본 크기를 미리 정해 끝까지 가거나 순차검정으로 반복 관측을 미리 계산에 반영해 5% 약속을 지키세요.
