# 11편. 두 학파 — 빈도주의 vs 베이지안

> 시리즈: 밑바닥부터 이해하는 A/B 테스트 통계
> 이 편에서 배우는 것: 지금까지 써 온 p-value 방식(빈도주의)과, "B가 이길 확률"을 직접 계산하는 베이지안 방식의 근본 차이.

콩마켓 실험이 끝나고 결과를 보고하는 자리. 여러분이 "p-value가 0.005라 통계적으로 유의합니다"라고 말하자, 팀장님이 되묻습니다. "그래서 초록 버튼이 파랑을 이길 확률이 몇 퍼센트예요?" 여러분은 잠깐 말문이 막힙니다. 왜냐하면 **p-value는 그 질문에 답하는 숫자가 아니기 때문**입니다. 이 어색한 순간이 통계학의 두 학파, 빈도주의와 베이지안이 갈라지는 지점입니다.

## 우리가 지금까지 쓴 방식: 빈도주의

**빈도주의(frequentist)** — 확률을 "같은 실험을 무한히 반복했을 때의 빈도"로 보는 관점 — 는 이 시리즈가 4편부터 줄곧 써 온 방식입니다. 핵심 질문이 독특합니다.

> "만약 A와 B가 **진짜로 차이가 없다면**, 지금 본 것만큼(또는 그 이상)의 차이가 우연히 나올 확률은?"

이 확률이 바로 p-value입니다. 콩마켓에서는 z = 2.81, 양측 p-value ≈ 0.005가 나왔습니다(6편). 해석은 이렇습니다. "버튼 효과가 정말 없다면, 이만한 차이가 순전히 운으로 나올 확률은 0.5%밖에 안 된다. 그렇게 드문 일이 실제로 일어났다고 보긴 어려우니, '차이가 없다'는 가정을 버리자."

여기서 미묘하지만 중요한 점이 있습니다. 빈도주의에서 "참값"은 고정된 하나의 숫자입니다. 흔들리는 것은 참값이 아니라 **우리가 뽑은 표본**입니다. 그래서 빈도주의는 "B의 진짜 전환율이 5.6%일 확률"이라는 문장을 아예 만들 수 없습니다. 진짜 전환율은 이미 하나로 정해져 있으니 "확률"을 붙일 대상이 아니라고 보기 때문입니다.

바로 이 지점이 팀장님 질문과 어긋납니다. 팀장님이 궁금한 건 "**B가 A보다 나을 확률**"인데, 빈도주의는 "차이가 없다는 가정 하에서 데이터가 나올 확률"만 말해줍니다. 방향이 반대인 셈입니다. p-value가 0.005라고 해서 "B가 이길 확률 99.5%"라고 말하면 **틀립니다.** (이건 흔한 오해라 6편에서도 짚었습니다.)

> **한 줄 기억법 — "우연일 확률" vs "참일 확률"**
> 두 학파의 차이는 결국 **조건부확률의 세로줄(|) 앞뒤가 뒤바뀐 것**입니다.
> - **빈도주의:** `P(데이터 | 가설)` — "차이가 없다고 **가정하면**, 이 데이터가 **우연히** 나올 확률" → 한마디로 **"이게 우연일 확률"**
> - **베이지안(다음 절):** `P(가설 | 데이터)` — "이 데이터를 **봤을 때**, '초록이 낫다'가 **참일** 확률" → 한마디로 **"이게 진짜(참)일 확률"**
>
> 조건과 결과가 반대라, 둘은 **서로 뒤집힌 질문**에 답합니다. p=0.005(우연일 확률)를 "이길 확률 99.5%"(참일 확률)로 바꿔 읽으면 안 되는 이유가 바로 이것입니다. (베이지안은 "참일 확률"을 직접 계산하는데, 그렇다고 "필연=100%"라는 뜻은 아니고 어디까지나 확률입니다. 우리 예에서는 곧 약 99.75%로 나옵니다.)

## 다른 관점: 베이지안

**베이지안(Bayesian)** — 확률을 "믿음의 정도"로 보고, 데이터로 그 믿음을 갱신하는 관점 — 은 질문을 뒤집습니다.

> "데이터를 봤으니, **B가 A보다 나을 확률**은 이제 얼마인가?"

팀장님 질문에 정면으로 답하는 방식입니다. 베이지안은 세 단계로 움직입니다.

1. **사전분포(prior)** — 데이터를 보기 전에 갖고 있던 믿음. "B의 전환율이 몇 %쯤일까?"에 대한 초기 추측입니다.
2. **가능도(likelihood)** — 데이터가 각 후보를 얼마나 지지하는지. 데이터 자체는 "관측한 구매·미구매 횟수"이고, 가능도는 후보 전환율 `p`가 이 데이터를 얼마나 그럴듯하게 만드는지를 나타내는 함수입니다. 성공 `s`회·실패 `f`회를 봤다면 `p^s (1−p)^f` 에 비례합니다. 예를 들어 후보 전환율이 5%(0.05)라면, 이 후보가 콩마켓 B의 관측(구매 1,232·미구매 20,768)을 만들어낼 그럴듯함은 `0.05^1232 × 0.95^20768`에 비례합니다. 값 자체는 작지만, 여러 후보끼리 "어느 쪽이 더 그럴듯한가"를 비교하는 용도라 절대값은 중요하지 않습니다. 한 가지 주의할 점은 **가능도는 사후확률 자체가 아니라는 것**입니다 — 사후확률은 여기에 prior를 곱하고 전체를 다시 정규화해야 나옵니다.
3. **사후분포(posterior)** — 사전 믿음을 데이터로 갱신한 결과. "이제 B의 전환율은 이 근처일 것이다"라는 최종 믿음입니다.

한 문장으로 줄이면 **"사전 믿음 + 데이터 = 사후 믿음"** 입니다. 데이터가 많아질수록 처음 믿음(prior)의 영향은 옅어지고, 사후분포는 진실 주변으로 점점 좁고 뾰족해집니다.

## Beta 분포: 전환율을 위한 믿음의 그릇

전환율처럼 "0과 1 사이의 비율"에 대한 믿음을 담기에 딱 좋은 도구가 **Beta 분포(Beta distribution)** 입니다. Beta 분포는 숫자 두 개, `Beta(α, β)`로 정해지는데 직관이 아주 단순합니다. (여기서 `α`와 `β`는 Beta 분포의 모양 파라미터이며, 앞 편의 유의수준 `α`·2종 오류 `β`와는 이름만 같고 관계가 없습니다.)

- `Beta(a₀, b₀)` prior에서 성공(구매) `s`회·실패(미구매) `f`회를 관측하면, posterior는 `Beta(a₀ + s, b₀ + f)`가 됩니다.
- 이 글처럼 시작 prior가 `a₀ = b₀ = 1`이면 `α = s + 1`, `β = f + 1`입니다. 그래서 대략 "α ≈ 성공 횟수 + 1, β ≈ 실패 횟수 + 1"로 기억해도 됩니다.

데이터를 보기 전, "아무것도 모른다"는 상태는 `Beta(1, 1)` — 성공도 실패도 0번 본 상태 — 로 표현합니다. 이건 0~1 사이가 전부 똑같이 그럴듯한 **균등 사전분포(uniform prior)** 입니다. 다만 `Beta(1,1)`은 `p` 척도에서 균등한 **단순한** 사전분포일 뿐, 유일하게 올바른 "중립" prior는 아닙니다. 그래도 어떤 전환율도 특별히 편들지 않는 무난한 출발점이라 흔히 씁니다.

여기에 콩마켓 데이터를 먹입니다. 갱신 규칙이 놀랍도록 간단합니다. **본 성공 횟수를 α에, 본 실패 횟수를 β에 그냥 더하면 끝**입니다.

- A(파랑): 22,000명 중 1,100명 구매 → `Beta(1 + 1100, 1 + 20900)` = **Beta(1101, 20901)**
- B(초록): 22,000명 중 1,232명 구매 → `Beta(1 + 1232, 1 + 20768)` = **Beta(1233, 20769)**

처음엔 0~1 전체에 납작하게 퍼져 있던 믿음이, 데이터 22,000개를 보고 나니 A는 5.0% 근처, B는 5.6% 근처에 좁고 뾰족하게 모입니다. **데이터를 볼수록 분포가 좁아진다** — 이게 "불확실성이 줄어든다"의 그림입니다. 관측이 많을수록 우리는 진짜 전환율이 어디쯤인지 더 확신하게 됩니다.

## "B가 이길 확률"을 직접 계산하기

이제 팀장님 질문에 답할 차례입니다. A의 사후분포와 B의 사후분포, 두 종 모양이 5.0%와 5.6% 근처에 나란히 서 있습니다. 서로 살짝 겹칩니다. `P(B > A)`는 "B에서 뽑은 값이 A에서 뽑은 값보다 클 확률"입니다.

공식으로 풀기는 까다롭지만, **몬테카를로(Monte Carlo)** — 수많은 무작위 표본을 뽑아 비율로 답을 추정하는 방법 — 를 쓰면 초등학교 산수 수준으로 간단해집니다. "A 분포에서 하나 뽑고, B 분포에서 하나 뽑아, B가 크면 한 표. 이걸 수십만 번 반복해서 득표율을 센다." 그게 곧 `P(B > A)`입니다.

```python
import random

# 콩마켓 최종 결과
a_buy, a_visit = 1100, 22000
b_buy, b_visit = 1232, 22000

# 균등 사전분포 Beta(1,1) -> 사후분포 = Beta(1+구매, 1+미구매)
a_alpha, a_beta = 1 + a_buy, 1 + (a_visit - a_buy)   # Beta(1101, 20901)
b_alpha, b_beta = 1 + b_buy, 1 + (b_visit - b_buy)   # Beta(1233, 20769)

# 몬테카를로로 P(B > A)
random.seed(0)
N = 500_000
wins = 0
for _ in range(N):
    a = random.betavariate(a_alpha, a_beta)   # A 사후분포에서 한 번 뽑기
    b = random.betavariate(b_alpha, b_beta)   # B 사후분포에서 한 번 뽑기
    if b > a:
        wins += 1

print(f"A ~ Beta({a_alpha}, {a_beta})")
print(f"B ~ Beta({b_alpha}, {b_beta})")
print(f"P(B > A) = {wins / N:.4%}")
```

`scipy`가 없어도 파이썬 표준 라이브러리 `random.betavariate`만으로 돌아갑니다. 실행 결과입니다.

```
A ~ Beta(1101, 20901)
B ~ Beta(1233, 20769)
P(B > A) = 99.7494%
```

**P(B가 A보다 낫다) ≈ 99.75%.** 이 `Beta(1,1)` prior와 독립 Bernoulli 모형에서 정확히 적분하면 `P(p_B > p_A | data) ≈ 99.7515%`이고, 위 몬테카를로 추정치 `99.7494%`는 그 참값 근처의 근삿값입니다(둘 다 99.75%로 반올림). 이제 팀장님께 이렇게 답할 수 있습니다. "초록 버튼이 파랑을 이길 확률이 약 99.7%입니다." p-value 0.005보다 훨씬 알아듣기 쉬운 문장입니다. (뽑는 횟수를 늘릴수록 몬테카를로 추정치는 참값 99.7515% 근처로 점점 촘촘히 수렴합니다.)

## 두 학파의 장단점

어느 쪽이 정답이라기보다, 서로 다른 도구입니다.

| | 빈도주의 | 베이지안 |
|---|---|---|
| 답하는 질문 | "차이가 없다고 가정할 때 지금 관측한 차이만큼 또는 더 극단적인 결과가 나올 확률" | "B가 A보다 나을 확률" |
| 결과 해석 | 간접적(익숙해져야 함) | 직관적("99.7%") |
| 사전 믿음(prior) | 안 씀 | 명시적으로 씀(선택 논란) |
| 조기 중단(peeking) | 취약 — 보정 필요(8편) | 중간 해석은 가능하나 조기 종료엔 보정 필요 |
| 규제/표준 | 널리 표준으로 통용 | 도입 늘어나는 중 |

베이지안의 강점은 해석이 직관적이라는 점입니다. 사후분포는 중간에 관측한 뒤에도 그대로 해석할 수 있어, 결과를 들여다보며 판단하기가 편합니다. 다만 "`P(B>A)`가 95%를 처음 넘으면 멈춘다" 같은 **고정된 posterior 문턱으로 조기 종료하면, 장기적으로 의사결정 오탐률(잘못된 승자 선언)이 커질 수 있습니다.** posterior가 계속 갱신된다는 사실이 그 자체로 오탐률을 제어해 주지는 않으니, 중단 규칙은 손실·오탐 기준과 함께 보정해야 안전합니다([GrowthBook 통계 개요](https://docs.growthbook.io/statistics/overview)). 또 다른 약점은 **사전분포를 어떻게 정하느냐**를 두고 논란이 생길 수 있다는 것입니다. 우리는 단순한 균등 `Beta(1,1)`을 썼지만, 누군가 "B에 유리한 prior를 몰래 넣은 것 아니냐"고 의심할 여지가 있습니다. 데이터가 22,000개처럼 충분히 많으면 prior의 영향은 거의 사라지지만, 데이터가 적을 때는 prior 선택이 결과를 좌우할 수 있어 주의가 필요합니다.

반대로 빈도주의는 오랜 세월 표준으로 자리 잡아 규제·논문에서 널리 통용되고, prior라는 주관적 선택이 없다는 점이 강점입니다. 실무에서는 둘 중 하나만 옳다고 고집하기보다, 질문에 맞는 쪽을 골라 쓰는 편이 낫습니다.

> **실무 요령 — 어느 걸 보고, 언제 둘이 갈리나**
> - **하나를 미리 정해 그것 하나로 결정하세요.** 둘 다 보고 유리한 쪽을 채택하면 골라잡기(cherry-picking)라 가짜 승자가 늘어납니다. 방식과 문턱을 **실험 전에** 못 박는 게 원칙입니다.
> - **어느 쪽?** 규제·표준·"가짜양성 ≤ 5%" 보증이 필요하면 **빈도주의**, 의사결정 소통이 직관적이어야 하면("이길 확률 %") **베이지안**. 대부분의 팀은 조직 차원에서 **하나로 통일**합니다.
> - **둘이 갈릴 수 있나?** 대부분 일치합니다(표본이 크면 수렴). 다만 **① 경계선 결과**(예: p=0.06인데 Chance to Win 94%)나 **② 표본이 작고 prior가 강할 때** 갈릴 수 있습니다. 갈리는 지대는 "증거가 아직 애매하다"는 신호이기도 하니 보수적으로 판단하세요.
> - 두 값은 방향이 반대라 **직접 환산되지 않습니다**(p=0.005 ≠ 1−0.995). 숫자를 1:1로 비교하지 마세요.

## 프레임워크에서 어디에 쓰이나

오픈소스 A/B 프레임워크들은 흔히 두 엔진을 모두 제공합니다. GrowthBook도 설정에서 빈도주의 엔진(z-test·신뢰구간·p-value)과 베이지안 엔진을 골라 쓸 수 있습니다. 다만 이 편에서 손으로 짠 arm별 `Beta-Binomial` 사후분포는 **이진 지표 베이지안의 원리를 학습하기 위한 구현**이라는 점을 짚어 둡니다. 현재 GrowthBook의 베이지안 엔진은 arm별 Beta가 아니라, 효과(effect)와 표준오차를 정규 근사한 뒤 treatment effect에 대한 Normal prior를 결합해 "이길 확률(Chance to Win)"과 예상 손실을 계산합니다([GrowthBook 통계 상세](https://docs.growthbook.io/statistics/details)). 구현은 다르지만 "사후분포로 `P(B>A)`를 직접 답한다"는 베이지안의 심장은 똑같습니다. 그리고 이 `P(B>A)`와 사후분포 표본은 다음 편에서 다룰 Multi-armed Bandit이 "어느 arm에 트래픽을 더 줄지" 실시간으로 정하는 데 그대로 쓰입니다.

## 한 줄 정리

빈도주의는 "차이가 없다고 가정할 때 지금 관측한 차이만큼 또는 더 극단적인 결과가 나올 확률(p-value)"을, 베이지안은 "B가 A보다 나을 확률(콩마켓 ≈ 99.75%)"을 답합니다 — 같은 데이터에 던지는 질문이 다를 뿐입니다.
