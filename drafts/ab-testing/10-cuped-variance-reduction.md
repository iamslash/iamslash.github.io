# 10편. 더 적은 사람으로 더 빨리 — CUPED와 분산감소

> 시리즈: 밑바닥부터 이해하는 A/B 테스트 통계
> 이 편에서 배우는 것: 실험 전 데이터로 노이즈를 줄여서, 같은 결론을 더 적은 사람으로 더 빨리 내는 법(CUPED).

콩마켓에서 '구매하기' 버튼 실험을 돌리려면 arm당 약 22,000명, 그러니까 대략 2주치 트래픽이 필요했습니다(7편). 그런데 팀장님이 묻습니다. "이거 꼭 2주나 기다려야 해요? 일주일이면 안 돼요?" 방문자를 마음대로 늘릴 수는 없습니다. 하지만 방법이 하나 더 있습니다. **필요한 표본 수 자체를 줄이는 것**입니다. 이번 편의 주인공 CUPED가 바로 그 일을 합니다.

## 왜 표본이 그렇게 많이 필요할까

3편에서 신뢰구간(confidence interval) — 반복 실험에서 정해진 비율의 구간이 참값을 포함하도록 만든 추정 범위 — 의 폭이 표준오차에 비례한다고 했습니다. 그리고 표준오차(standard error) — 표본 평균이 운으로 얼마나 출렁이는지의 크기 — 는 이렇게 생겼습니다.

```
표준오차 = 표준편차 / sqrt(표본 크기)
```

여기서 위쪽 **표준편차(standard deviation)** — 데이터가 평균에서 얼마나 흩어져 있는지 — 가 바로 "노이즈(noise)"입니다. 노이즈가 크면 표준오차가 크고, 표준오차가 크면 신뢰구간이 넓어져서 A와 B의 차이가 잘 안 보입니다. 이걸 좁히는 길은 딱 두 가지입니다.

1. 분모의 **표본 크기를 키운다** → 사람을 더 모은다(느리고 비싸다).
2. 분자의 **표준편차(노이즈)를 줄인다** → 이번 편의 아이디어.

분산(variance) — 표준편차를 제곱한 값, 흩어짐의 크기 — 을 절반으로 줄이면 필요한 표본도 대략 절반이 됩니다. 사람을 더 모으지 않고도 실험 기간을 반으로 줄일 수 있다는 뜻입니다. 솔깃하지 않나요?

## 노이즈의 정체: 원래 큰손과 작은손

콩마켓의 연속형 보조 지표로 **방문자당 매출**(원)을 봅시다. 여기서 지표는 "구매자 1인당"이 아니라 "**방문자 1인당**"입니다. 산 사람은 결제액을, 안 산 사람은 **0원**을 기록해서 arm당 방문자 22,000명 전원을 그대로 셉니다. (구매자만 따로 떼어 보면 "누가 구매자가 되었는가" 자체가 버튼 효과에 영향을 받아 표본이 편향될 수 있습니다. 방문자 전체를 보면 이 문제가 없고 표본 수도 22,000명으로 고정됩니다.) 이 값은 사람마다 천차만별입니다. 몇십만 원씩 쓰는 큰손도 있고, 대부분은 아무것도 안 사서 0원입니다. 이 엄청난 개인차가 바로 노이즈의 대부분입니다.

그런데 생각해 봅시다. **버튼 색을 파랑에서 초록으로 바꾼다고 큰손이 작은손이 되지는 않습니다.** 큰손은 초록 버튼을 봐도 여전히 큰손입니다. 즉 매출의 출렁임 대부분은 "버튼 효과"가 아니라 "원래 그 사람이 얼마나 쓰는 사람인가"에서 옵니다.

여기서 핵심 아이디어가 나옵니다.

> 각 유저가 **원래 얼마나 쓰는 사람인지**를 우리는 실험 전부터 알고 있습니다(예: 지난달 매출). 그 "원래 성향"으로 설명되는 개인차를 미리 줄이면, 버튼이 만든 효과를 잡음 속에서 더 또렷하게 추정할 수 있습니다.

비유하자면 시끄러운 카페에서 친구 목소리를 듣는 상황입니다. 카페의 배경 소음(원래 성향으로 설명되는 부분)을 노이즈 캔슬링으로 많이 줄이면, 친구 목소리(버튼 효과)가 훨씬 또렷하게 들립니다. 신호는 그대로인데 잡음이 줄었으니 **신호 대비 잡음(signal-to-noise)** 이 좋아진 것입니다. (단, 노이즈 캔슬링이 모든 소음을 지우지는 못하듯, CUPED도 X로 설명되는 잡음만 줄일 뿐 설명되지 않는 개인차·측정 잡음은 남습니다.)

## CUPED: 실험 전 데이터로 성향을 빼기

이 아이디어에 붙은 이름이 **CUPED(Controlled experiment Using Pre-Experiment Data)** — 실험 전 데이터를 이용한 통제 실험 — 입니다. 이름이 길지만 하는 일은 한 문장입니다. "각 유저의 실험 전 데이터(X)를 이용해, 실험 지표(Y)에서 원래 성향만큼을 빼준다."

기호를 정리하면 이렇습니다.

- `Y` : 실험 기간의 지표 (이번 달의 방문자당 매출)
- `X` : 실험 전의 지표 (지난달의 방문자당 매출) — 이걸 **공변량(covariate)**이라고 부릅니다. 공변량은 결과 `Y`의 개인차를 실험 전에 미리 설명해 주는 보조 변수입니다.
- `X평균` : 모든 유저의 X 평균

보정된 값 `Y'`는 다음과 같이 만듭니다.

```
Y' = Y − θ · (X − X평균)
```

- `(X − X평균)` : 이 유저가 평균보다 원래 얼마나 큰손/작은손인지
- `θ`(세타) : 그 성향을 Y에서 얼마나 빼줄지 정하는 계수

`θ`는 사실 "지난달 매출(X)이 1만원 높은 사람이 이번 달(Y)에 평균 얼마나 더 쓰는가"를 나타내는 기울기입니다. X로 Y를 가장 잘 예측하는 직선의 기울기예요. 그래서 각 유저의 Y에서 "θ·(X−X평균)"만큼(=지난달 성향으로 설명되는 몫)을 빼주는 게 자연스럽습니다.

`θ`는 아래 공식으로 딱 정해집니다. cov는 공분산(covariance) — 두 값이 같이 움직이는 정도 — 입니다.

```
θ = cov(X, Y) / var(X)
```

여기서 두 가지 성질이 나옵니다.

1. **처리효과의 기대값이 유지됩니다.** 무작위 배정과 pre-treatment 조건(공변량 X가 실험 전에 결정됨) 아래에서 CUPED는 처리효과의 기대값을 그대로 지키며, 같은 표본에서 θ를 추정한 경우에도 큰 표본에서는 이 성질에 수렴합니다(작은 표본에서는 아주 약간의 유한표본 편향이 남을 수 있습니다). 직관은 이렇습니다. 무작위 배정이라 두 arm의 실험 전 성향은 평균적으로 같습니다(반복하면 X 평균 차이가 0으로 모입니다). 그래서 참효과를 왜곡하지 않습니다. 단 이번 한 번은 우연히 B에 큰손이 더 몰릴 수 있는데(코드에서 X_B평균 > X_A평균), CUPED가 이 우연한 불균형까지 걷어내므로 보정 전후 B−A가 달라집니다. 즉 매번의 평균값을 "그대로 두는" 게 아니라, 우연한 불균형을 제거해 더 믿을 만한 추정으로 바꾸는 것입니다.
2. **분산이 줄어듭니다.** 얼마나? 딱 이만큼입니다.

```
Y'의 분산 ≈ Y의 분산 × (1 − 상관계수²)
```

**상관계수(correlation)** — 두 값이 함께 움직이는 정도를 −1~+1로 나타낸 수 — 는 **절댓값**이 클수록 분산을 많이 줄여 줍니다. 부호는 상관없습니다. 상관이 +0.7이든 −0.7이든 `(±0.7)² = 0.49`, 즉 이론적으로 분산의 약 49%를 걷어냅니다(공변량이 Y와 음의 상관이어도 똑같이 쓸모가 있다는 뜻입니다). 실험 전과 실험 중 매출의 상관이 0.7이라면 `1 − 0.7² = 0.51`, 분산이 약 절반으로 줄고, 그래서 **필요 표본도 약 절반**이 됩니다. 지난달 데이터 한 컬럼을 붙였을 뿐인데 실험 기간이 반토막 나는 셈입니다.

## Python으로 확인하기

말로만 하면 못 믿으니 직접 시뮬레이션해 봅시다. 지난달 매출 `X`와 이번 달 매출 `Y`가 상관 구조를 갖도록 예시 콩마켓 데이터를 만들고, 두 arm(A/B)의 **방문자당 매출 차이(B−A)**를 CUPED 전후로 추정해 신뢰구간이 얼마나 좁아지는지 비교합니다. 아래 데이터는 "실험 전 성향이 결과와 상관을 갖는다"는 구조를 보여 주기 위한 **예시 데이터**이며, 앞서 나온 전환율 실험의 고정 숫자와는 별개입니다. 비구매자는 0원으로 포함해 arm당 22,000명을 그대로 씁니다.

```python
import numpy as np

rng = np.random.default_rng(42)
sigmoid = lambda t: 1 / (1 + np.exp(-t))
N = 22000  # arm당 방문자 수

# 아래 make_arm은 예시 데이터 생성기입니다.
# z는 방문자의 숨은 구매 성향, sigmoid는 이를 0~1 구매 확률로,
# exp는 오른쪽 꼬리가 긴 양수 결제액을 만듭니다.
# CUPED 자체는 아래 'CUPED 보정' 블록부터입니다.
def make_arm(button_boost):
    """한 arm의 (지난달 매출 X, 이번 달 매출 Y). 비구매자는 0원으로 포함."""
    # 지속되는 구매 성향 z: 지난달과 이번 달에 똑같이 작용(큰손일수록 큼)
    z = rng.standard_normal(N)
    def revenue(boost):
        bought = rng.random(N) < sigmoid(-4.2 + boost + 1.9 * z)
        amount = np.exp(9.5 + 1.4 * z + 0.3 * rng.standard_normal(N))
        return np.where(bought, amount, 0.0)   # 안 산 사람은 0원
    X = revenue(0.0)           # 실험 전(지난달): 버튼 효과 없음
    Y = revenue(button_boost)  # 실험 기간(이번 달)
    return X, Y

# A: 파란 버튼(효과 0), B: 초록 버튼(구매 성향을 살짝 높임)
XA, YA = make_arm(0.0)
XB, YB = make_arm(0.35)

# --- CUPED 보정: theta = cov(X,Y)/var(X), 두 arm을 합쳐 추정 ---
X_all = np.concatenate([XA, XB])
Y_all = np.concatenate([YA, YB])
theta = np.cov(X_all, Y_all, bias=True)[0, 1] / np.var(X_all)
Xbar = X_all.mean()            # 공통 중심값
adjust = lambda Y, X: Y - theta * (X - Xbar)
YA_adj, YB_adj = adjust(YA, XA), adjust(YB, XB)

# --- B-A 차이와 95% 신뢰구간: SE = sqrt(var_A/n_A + var_B/n_B) ---
def diff_ci(yA, yB):
    diff = yB.mean() - yA.mean()
    se = np.sqrt(yA.var(ddof=1) / len(yA) + yB.var(ddof=1) / len(yB))
    return diff, 1.96 * se

diff0, ci0 = diff_ci(YA, YB)           # CUPED 전
diff1, ci1 = diff_ci(YA_adj, YB_adj)   # CUPED 후

corr = np.corrcoef(X_all, Y_all)[0, 1]
var_reduction = 1 - adjust(Y_all, X_all).var() / Y_all.var()

print(f"theta            = {theta:.3f}")
print(f"corr(X, Y)       = {corr:.3f}")
print(f"분산 감소율        = {var_reduction:.3f}")
print(f"공식 검산 corr^2   = {corr**2:.3f}")
print(f"X_A평균={XA.mean():,.0f}원  X_B평균={XB.mean():,.0f}원")
print(f"B-A before = {diff0:,.0f}원  (95% CI ±{ci0:,.0f}원)")
print(f"B-A after  = {diff1:,.0f}원  (95% CI ±{ci1:,.0f}원)")
print(f"CI 폭 축소율      = {1 - ci1/ci0:.3f}")
print(f"필요 표본 배수    = {(ci1/ci0)**2:.3f}")
```

실행 결과입니다.

```
theta            = 0.711
corr(X, Y)       = 0.717
분산 감소율        = 0.514
공식 검산 corr^2   = 0.514
X_A평균=9,770원  X_B평균=10,539원
B-A before = 1,757원  (95% CI ±1,454원)
B-A after  = 1,209원  (95% CI ±1,013원)
CI 폭 축소율      = 0.303
필요 표본 배수    = 0.486
```

읽어봅시다. 먼저 분산 감소율 **0.514**를 봅니다. 이 값은 이론값 `상관계수²`(0.717² ≈ 0.514)에 대한 **독립적인 검증이 아니라 공식 검산**입니다. 동일 표본에서 최적 θ를 쓰면 "분산 감소 = corr²"가 공식상 성립하므로, 두 값은 원래 일치합니다(그래서 라벨도 "실측"이 아니라 "공식 검산"입니다). 그 결과 B−A 차이의 신뢰구간 반폭이 **±1,454원에서 ±1,013원으로 30% 좁아졌고**, 같은 정밀도를 내는 데 필요한 표본이 원래의 **0.486배**로 줄었습니다. 이 방문자당 매출 지표가 원래 22,000명을 요구하도록 설계됐다면, 같은 기대 정밀도에는 약 **10,700명**이 필요합니다. 주 지표인 전환율의 22,000명 요구량은, 전환율에도 별도로 CUPED를 적용해 감소율을 확인하지 않는 한 그대로입니다. 그래도 이 보조 지표만 놓고 보면 팀장님 요청에 한 걸음 다가선 셈입니다.

한 가지 눈여겨볼 점은 B−A 추정치 자체가 1,757원에서 1,209원으로 바뀌었다는 것입니다. 이번 실험에서는 우연히 B 그룹에 원래 돈을 더 쓰던 방문자가 조금 더 몰렸습니다(실험 전 평균이 `X_A평균=9,770원 < X_B평균=10,539원`). CUPED는 이 우연한 실험 전 불균형을 걷어내므로, 보정 후 추정치가 그만큼 내려간 것입니다(`1,757 − 0.711 × (10,539 − 9,770) ≈ 1,209`). 무작위 배정에서는 이런 불균형의 기대값이 0이라 추정량이 편향되지는 않지만, **한 번의 실험에서는 이렇게 값이 달라질 수 있습니다.** 보정 후 값이 이번 실험에서는 더 믿을 만한 추정입니다.

## 쓸 때 주의할 점

CUPED는 공짜 점심에 가깝지만, 몇 가지 함정이 있습니다.

- **X는 반드시 "실험 전" 데이터여야 합니다.** 실험 중에 생긴 값(예: 실험 기간의 클릭 수)을 X로 쓰면, 버튼 효과가 X에 섞여 들어가 버립니다. 그러면 순수 효과까지 같이 빼버려서 결과가 편향됩니다. "실험 전(pre-experiment)"이라는 이름이 괜히 붙은 게 아닙니다.
- **상관이 낮으면 이득도 적습니다.** X와 Y의 상관이 0.1이면 분산 감소는 고작 1%입니다. 지표와 잘 상관되는 실험 전 데이터가 있을 때만 효과가 큽니다.
- **신규 유저는 X가 없습니다.** 지난달 기록이 없는 신규 방문자는 X를 평균값으로 채우는 등 별도 처리가 필요합니다.
- 무조건 절반이 되는 것은 아닙니다. 감소량은 데이터의 상관에 달려 있어서, 실험마다 다릅니다.

## 프레임워크에서 어디에 쓰이나

GrowthBook 같은 오픈소스 A/B 프레임워크는 CUPED(문서에 따라 "regression adjustment" 또는 "variance reduction"으로도 부릅니다)를 지표 계산 단계에 내장하고 있습니다. 프레임워크는 각 유저의 실험 전 지표(X)를 조회해 두었다가, 결과를 집계할 때 `Y' = Y − θ(X − X평균)`로 보정한 값으로 신뢰구간과 p-value를 계산합니다. 우리가 직접 구현한다면, 지표 파이프라인에 "실험 전 값을 join → θ 추정 → 보정값 산출"이라는 한 단계를 끼워 넣는 것으로, 표본 수를 늘리지 않고 실험 속도를 끌어올리는 기능이 됩니다.

> **실물 참고(무료 vs 상용).** 단, GrowthBook에서 이 **CUPED(분산감소)는 상용(Cloud의 Pro / 셀프호스트의 Enterprise) 기능**이라 무료 셀프호스트 버전에선 잠겨 있습니다. 원리 자체는 위 `Y' = Y − θ(X − X평균)` 한 줄이라, 지표 파이프라인에 직접 끼워 넣어 재현할 수 있습니다.

## 한 줄 정리

실험 전 데이터로 각 유저의 원래 성향을 걷어내면, 무작위 배정·pre-treatment 조건에서 처리효과의 기대값은 유지하면서 분산만 `상관계수²`만큼 줄어들어 — 같은 결론을 더 적은 사람으로 더 빨리 낼 수 있습니다.
