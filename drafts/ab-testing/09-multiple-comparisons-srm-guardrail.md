# 9편. 우연한 승자들 — 다중비교·SRM·가드레일

> 시리즈: 밑바닥부터 이해하는 A/B 테스트 통계
> 이 편에서 배우는 것: 지표를 여러 개 보면 왜 가짜 승자가 늘어나는지, 배정 자체가 틀어졌는지 어떻게 잡아내는지(SRM), 그리고 이기려다 다른 걸 망치지 않게 지키는 방법.

8편에서는 "같은 지표를 여러 번 훔쳐보면" 가짜 승자가 폭증한다는 걸 봤습니다. 이번엔 사촌 격인 함정들입니다. "**한 번에 여러 지표를**" 보면 어떻게 될까요? 그리고 애초에 50:50 배정이 제대로 됐는지는 어떻게 믿죠? 콩마켓 실험을 계속 예로 들며 세 가지 안전장치를 배웁니다.

## 다중비교(multiple comparisons) — 로또를 많이 사면 하나쯤 당첨된다

콩마켓 초록 버튼(B) 실험을 하면서, 욕심이 생겨 한 번에 지표를 여러 개 봅니다. 전환율, 방문자당 매출, 재방문율, 장바구니 담기율, 리뷰 작성률… 이렇게 5개를 놓고 "이 중 하나라도 유의하게 좋아지면 성공이라고 하자"고 생각합니다.

문제는 5편에서 배운 그 5%입니다. 지표 하나를 볼 때 "진짜 차이가 없는데도 우연히 유의할 확률"이 5%였죠. **지표를 여러 개 보면 이 5%짜리 복권을 여러 장 사는 것**과 같습니다. 복권 한 장은 당첨 확률이 낮지만, 여러 장 사면 "하나쯤 당첨될" 확률은 쭉 올라갑니다.

모든 지표에 사실 차이가 없다고 가정하면, "적어도 하나가 우연히 유의할" 확률은 대략 `1 - (1 - 0.05)^지표수` 입니다. (지표들이 서로 독립이라는 단순화 가정 아래의 근사치입니다.)

```python
alpha = 0.05
for k in [1, 5, 10, 20]:
    fwer = 1 - (1 - alpha) ** k
    print(f"지표 {k:2d}개 -> 적어도 하나 가짜 유의할 확률 {fwer:.1%}")
```

```
지표  1개 -> 적어도 하나 가짜 유의할 확률 5.0%
지표  5개 -> 적어도 하나 가짜 유의할 확률 22.6%
지표 10개 -> 적어도 하나 가짜 유의할 확률 40.1%
지표 20개 -> 적어도 하나 가짜 유의할 확률 64.2%
```

지표 5개만 봐도 헛발질 확률이 22.6%, 20개를 보면 64%입니다. 대시보드에 지표를 잔뜩 띄워 놓고 "초록으로 칠해진 거 아무거나" 승자로 삼으면, 그건 승자가 아니라 그냥 **우연**일 가능성이 큽니다. 이렇게 여러 번의 비교에서 우연 승자가 늘어나는 문제를 **다중비교(multiple comparisons)** 문제라고 부릅니다.

## 보정하기 — 문턱을 지표 수만큼 엄격하게

해결의 방향은 8편과 똑같습니다. 복권을 여러 장 살 거면, 당첨 기준(문턱)을 그만큼 더 엄격하게 만들면 됩니다. 대표적인 두 가지만 봅니다.

**본페로니 보정(Bonferroni correction)** — 가장 단순하고 보수적입니다. 지표가 `m`개면 문턱을 `α/m`으로 낮춥니다. 5개를 본다면 각 지표는 0.05가 아니라 **0.01** 미만이어야 유의로 인정합니다. 복권을 5장 살 거니 한 장당 기준을 5배 빡세게 만드는 셈이죠. 확실하지만, 너무 엄격해서 진짜 효과까지 놓치기 쉽습니다(검정력 손해).

**FDR / 벤자미니-호크버그(Benjamini-Hochberg)** — 좀 더 균형 잡힌 방법입니다. "유의하다고 발표한 것들 중 가짜의 비율(False Discovery Rate)"을 일정 수준으로 관리합니다. 모든 가짜를 원천 봉쇄하는 본페로니보다 덜 엄격해서, 지표가 많을 때 진짜 효과를 더 잘 살려냅니다. p-value들을 작은 순서로 정렬한 뒤 순위에 비례한 문턱과 비교하는 방식입니다.

구체적으로 볼까요. 정렬된 p가 `.001, .013, .040, .090, .500`이라고 하겠습니다. BH는 네 단계로 움직입니다.

1. **정렬** — p-value를 작은 순서대로 늘어놓고 순위 `i`(1~5)를 매깁니다.
2. **순위별 문턱 계산** — 순위 `i`마다 문턱을 `(i/5)*0.05`로 둡니다. 그러면 문턱은 `.01, .02, .03, .04, .05`가 됩니다. 순위가 뒤로 갈수록 문턱이 조금씩 느슨해집니다.
3. **통과하는 가장 뒤 순위 찾기** — 각 순위에서 "p ≤ 문턱"인지 봅니다. 1위(.001 ≤ .01) ✓, 2위(.013 ≤ .02) ✓, 3위(.040 ≤ .03) ✗, 4위(.090 ≤ .04) ✗, 5위(.500 ≤ .05) ✗. 통과한 것 중 **가장 뒤(가장 큰 순위)**는 2위입니다.
4. **그 순위까지 기각** — 그 순위까지 한꺼번에 기각합니다. 즉 1·2위를 유의로 판정합니다(뒤에 통과 못 한 순위가 있어도, 앞의 통과 순위까지는 살립니다).

순위가 뒤로 갈수록 문턱을 조금씩 느슨하게 여는 이유는, 진짜 효과가 여럿이면 작은 p가 여러 개 몰려 나오기 때문입니다. 강한 증거 뒤에 붙은 것들도 어느 선까지 함께 인정하되, 가짜가 폭증하지 않도록 순위에 비례한 선에서 끊습니다.

> **고급 참고 — 의존성 조건.** 표준 BH는 검정들이 서로 독립이거나 적절한 양의 의존(positive dependence)을 가질 때 FDR을 제어합니다. 지표들이 복잡하게 얽혀 음의 상관까지 섞여 있으면 더 보수적인 변형(BH–Yekutieli 등)이 필요할 수 있습니다.

콩마켓 지표 5개의 p-value가 나왔다고 하고, 세 방식이 각각 몇 개를 "유의"라고 판정하는지 직접 돌려 봅시다.

```python
alpha = 0.05
pvals = [0.001, 0.013, 0.040, 0.090, 0.500]  # 콩마켓 지표 5개
m = len(pvals)

# 1) 보정 없음(순진한 방식): 그냥 0.05 미만이면 유의
naive = [p < alpha for p in pvals]

# 2) 본페로니: 문턱을 alpha/m 로 낮춤
bonf_thresh = alpha / m
bonf = [p <= bonf_thresh for p in pvals]

# 3) 벤자미니-호크버그(FDR): 정렬 후 p_(i) <= (i/m)*alpha 인 가장 큰 순위까지 기각
order = sorted(range(m), key=lambda i: pvals[i])
bh = [False] * m
kmax = 0
for rank, i in enumerate(order, start=1):
    if pvals[i] <= (rank / m) * alpha:
        kmax = rank
for rank in range(1, kmax + 1):
    bh[order[rank - 1]] = True

print("보정 없음 :", sum(naive), "개 유의")
print("본페로니  :", sum(bonf), "개 유의  (문턱", bonf_thresh, ")")
print("BH(FDR)   :", sum(bh),  "개 유의")
```

실제 출력입니다.

```
보정 없음 : 3 개 유의
본페로니  : 1 개 유의  (문턱 0.01 )
BH(FDR)   : 2 개 유의
```

같은 데이터인데 판정이 다릅니다. 보정 없이 보면 3개나 "이겼다"고 하지만, 그중 상당수는 우연일 수 있습니다. 본페로니는 가장 확실한 1개만 인정하고(안전하지만 깐깐), FDR은 그 중간인 2개를 인정합니다. 정답이 하나로 정해진 건 아니고, "얼마나 보수적으로 갈지"의 선택입니다. 다만 보정을 어디에 적용하는지가 중요합니다. 핵심은 **실험 전에 어떤 지표·변형·세그먼트를 하나의 의사결정 family로 묶을지 미리 정하고, 그 family에 보정을 적용한다**는 것입니다. 이때 의사결정을 좌우하는 단일 primary metric, 아이디어를 얻으려고 훑어보는 탐색적 secondary metric, 그리고 뒤에서 볼 별도의 비열등성 규칙을 쓰는 guardrail은 서로 역할이 다르니 구분해서 다뤄야 합니다. 콩마켓이라면 '전환율'은 배포를 결정하는 primary(주력), '리뷰 작성률'은 참고용 secondary, '방문자당 매출'은 나빠지면 안 되는 guardrail(수비수)입니다. 결정에 쓰지도 않을 지표까지 전부 한 family에 욱여넣고 보정하면, 정작 중요한 primary metric의 검정력만 깎아먹습니다.

## SRM(sample ratio mismatch) — 저울이 애초에 기울어졌다면

지금까지는 "50:50 배정이 제대로 됐다"는 전제 아래 이야기했습니다. 그런데 이 전제 자체가 깨지면 어떤 정교한 검정도 의미가 없습니다.

**SRM(sample ratio mismatch, 표본 비율 불일치)** — 의도한 배정 비율(예: 50:50)과 실제로 각 그룹에 들어온 사람 수의 비율이 통계적으로 유의하게 어긋난 상태입니다.

콩마켓에서 방문자를 50:50으로 나눴는데, 실제 집계가 A 그룹 22,000명, B 그룹 21,000명이라고 해 봅시다. "1,000명 차이? 그럴 수도 있지"라고 넘기기 쉽지만, 총 43,000명 규모에서 이 정도 쏠림은 우연으로 보기 어렵습니다. 원인은 보통 **버그**입니다. 랜덤 배정 로직 오류, 특정 그룹의 리다이렉트 실패, 로그 유실, 봇 필터가 한쪽만 걸러냄… 배정 파이프라인 어딘가가 새고 있다는 신호죠.

이걸 감지하는 도구가 **카이제곱 적합도 검정(chi-square goodness-of-fit test)** 입니다. "관측된 그룹별 인원이, 기대한 비율(50:50)에서 얼마나 벗어났는가"를 하나의 p-value로 요약해 줍니다.

계산 과정도 어렵지 않습니다. 먼저 각 그룹의 **기대 인원**을 구하는데, 50:50이면 전체를 절반씩 나눈 값입니다(예: 총 43,000명이면 각 그룹 21,500명). 그다음 각 그룹마다 `(관측 − 기대)² / 기대`를 계산해서 전부 더합니다. 이 합이 **카이제곱 통계량**입니다. 관측이 기대치에 가까우면 분자가 작아 통계량이 0에 가깝고, 기대치에서 멀어질수록 통계량이 커집니다. 통계량이 클수록 p-value는 작아지고, p가 아주 작으면 "이 쏠림은 우연이라 보기 어렵다 = SRM 의심"입니다.

```python
from scipy import stats

def srm_check(counts, expected_ratio):
    """counts: 각 그룹 실제 배정 수 (예: [22000, 21000])
       expected_ratio: 의도한 배정 비율 (예: [0.5, 0.5])
       카이제곱 적합도 검정 -> p가 아주 작으면 SRM(배정 버그) 의심."""
    total = sum(counts)
    expected = [total * r for r in expected_ratio]
    chi2, p = stats.chisquare(f_obs=counts, f_exp=expected)
    return chi2, p

# 정상: 거의 50:50
chi2_ok, p_ok = srm_check([22000, 22000], [0.5, 0.5])
print(f"정상  22000 vs 22000: chi2={chi2_ok:.1f}, p={p_ok:.1f}")
# 버그 신호: 22000 vs 21000
chi2, p = srm_check([22000, 21000], [0.5, 0.5])
print(f"의심  22000 vs 21000: chi2={chi2:.1f}, p={p:.2e}")
```

실제 출력입니다.

```
정상  22000 vs 22000: chi2=0.0, p=1.0
의심  22000 vs 21000: chi2=23.3, p=1.42e-06
```

22,000 vs 22,000은 p=1.0으로 아무 문제 없습니다. 하지만 22,000 vs 21,000은 **p ≈ 0.0000014**, 즉 백만분의 1 수준입니다.

여기서 이 p-value를 오해하지 않는 게 중요합니다. 이건 "특정 버그가 있을 확률"도 아니고 "원인이 무엇인지"를 알려주는 값도 아닙니다. p-value가 말해 주는 건 딱 하나, **이 정도 쏠림은 계획한 50:50 배정과 양립하기 매우 어렵다**는 것뿐입니다. 아주 강한 SRM 신호인 거죠. 그러니 해야 할 일은 "버그 확정"이라고 단정하는 게 아니라, **이 실험 결과를 일단 무효로 취급하고 배정·노출·로그·필터·eligibility(대상 조건) 파이프라인을 하나씩 조사하는 것**입니다. 원인을 찾기 전에는 전환율 차이든 p-value든 효과를 해석하지 않습니다.

여기서 가장 중요한 실무 규칙: **SRM이 뜨면 실험 결과(전환율 차이, p-value 등)를 절대 해석하지 마세요.** 저울 자체가 기울어져 있는데 무게를 재 봐야 소용없습니다. 초록 버튼이 이겼든 졌든, 그 결과는 배정·노출·로그·필터·대상 조건 문제로 생긴 착시일 수 있습니다. 결과 해석을 중단하고 **SRM의 원인부터 조사하는 것**이 순서입니다. 그래서 SRM 체크는 실험 분석의 **맨 앞 관문**에 둡니다. 이걸 통과 못 하면 뒤 분석은 시작도 하지 않습니다.

## 가드레일 지표(guardrail metrics) — 이기려다 다른 걸 망치지 않기

마지막 안전장치입니다. 초록 버튼이 전환율을 올렸다고 칩시다. 축하할 일이지만, 한 가지 지표만 보면 함정에 빠질 수 있습니다. 혹시 초록 버튼 페이지가 이미지가 무거워서 **로딩이 느려졌다면**? 당장의 클릭은 늘었어도 페이지가 버벅여서 장기적으로 사용자가 떠날 수 있습니다.

**가드레일 지표(guardrail metrics)** — 실험으로 개선하려는 핵심 지표(여기선 전환율)와 별개로, "이것만은 나빠지면 안 된다"고 정해 두고 감시하는 방어용 지표입니다. 공격은 핵심 지표로 하되, 수비는 가드레일로 하는 셈이죠.

콩마켓이라면 이런 것들이 가드레일이 됩니다.

- **페이지 로딩 속도** — 새 디자인이 페이지를 느리게 만들지 않았는가.
- **이탈률(bounce rate)** — 들어오자마자 나가 버리는 비율이 늘지 않았는가.
- **방문자당 매출** — 전환율(구매한 사람 비율)은 올랐지만, 저가 상품 구매만 늘어 방문자당 매출은 오히려 줄지 않았는가.

마지막 항목이 특히 중요합니다. 전환율만 보고 "이겼다"고 배포했는데 방문자당 매출이 줄었다면, 그건 이긴 게 아닙니다.

그런데 판정 규칙을 쓸 때 흔히 빠지는 함정이 있습니다. "가드레일이 **유의하게 나빠지지 않았으니** 안전하다"고 결론짓는 것입니다. 하지만 "유의하게 악화되지 않음"은 안전의 증거가 아닙니다. 가드레일 지표는 검정력이 낮은 경우가 많아서(우리가 표본 크기를 맞춘 건 핵심 지표였죠), 실제로는 꽤 큰 악화가 있어도 통계적으로 유의하지 않게 나올 수 있습니다. "유의하지 않다"는 건 "나빠지지 않았다"가 아니라 그냥 "잘 모르겠다"에 가깝습니다.

그래서 제대로 된 규칙은 **비열등성(non-inferiority)** 관점으로 씁니다: **핵심 지표가 사전에 정한 성공 기준을 통과하고, 동시에 각 가드레일의 신뢰구간이 "사전에 정한 허용 악화 한계"보다 나쁜 값을 배제할 때만 배포한다.** 예를 들어 "방문자당 매출이 2% 넘게 줄면 안 된다"고 미리 정했다면, 방문자당 매출 차이의 신뢰구간 하한이 −2%보다 위에 있어야(즉 −2%보다 나쁜 값을 배제해야) 통과입니다. 그냥 "유의하지 않으니 통과"가 아니라, **허용 한계보다 나쁜 시나리오를 데이터가 실제로 배제하는지**를 봐야 한다는 뜻이죠. (지표를 primary/guardrail로 나누고 각각에 맞는 규칙을 세우는 실무 감각은 GrowthBook의 [KPI 플레이북](https://www.growthbook.io/blog/kpi-playbook-ab-testing-metrics)에 잘 정리돼 있습니다.)

## 결과 읽는 순서 — 실전 요령 (총정리)

여기까지 배운 걸 하나로 묶으면, A/B 결과표는 **위에서 아래로 3단계 + 안전체크**로 읽습니다. 어떤 도구(GrowthBook 등)의 결과 화면이든 이 순서면 됩니다.

**① 이겼나? — 방향과 크기 (`% Change` = 효과 크기)**
- **↑ 양수**면 실험군이 좋음, **↓ 음수**면 오히려 나쁨. (효과는 +도 −도 될 수 있어서 기본이 양측 검정입니다, 6편)
- 이 값은 **상대(%)** 로도 **절대(%p)** 로도 볼 수 있습니다 — 콩마켓: **+12%(상대) = +0.6%p(절대)**. "몇 % 개선"과 "몇 %p 차이"는 다른 자라는 것만 기억하세요.

**② 진짜인가, 그냥 운인가? — 유의성 (셋 중 하나만 봐도 같은 답)**
- **p-value < 0.05** 인가? (4·5편)
- **신뢰구간(CI)이 0을 안 건드리나?** (3편) — 이게 CI를 읽는 핵심 규칙입니다.
- 프레임워크의 **"유의 / 승자(Won)" 배지**가 떴나?

**③ 얼마나 확신하나? — CI 넓이**
- 막대가 **좁으면** 확신, **넓으면** 아직 애매. 표본이 쌓일수록 좁아집니다(3·7편).

**판정 전 안전체크 (이걸 안 하면 위 셋이 무의미)**
- **SRM 통과했나** — 배정이 50:50으로 공정했나(이 편). 빨간불이면 숫자 믿지 말고 파이프라인부터.
- **미리 정한 표본·기간을 다 채웠나** — 유의 뜨자마자 멈추면 가짜 승자(peeking, 8편).
- **가드레일이 무너지지 않았나** — 이기려다 다른 핵심 지표를 망치지 않았나(이 편).

이걸 표로 요약하면:

| 유의성 | 효과 크기 | 결론 |
|---|---|---|
| 유의 ✅ | 의미 있게 큼(MDE 이상) | **배포** |
| 유의 ✅ | 눈곱만큼 | 도입 가치 재검토(MDE, 7편) |
| 유의 ❌ | — | **"차이 없다"가 아니라 "아직 모름"** — 표본 더 모으거나 접기 |

> **흔한 실수 3가지 (하지 마세요):** ① p가 크다 = "차이 없음 증명"이 아니라 "못 잡았다"일 뿐(5편). ② 여러 지표 중 하나 유의한 걸로 성공 선언 금지(보정, 이 편). ③ 매일 보다 유의 뜨자 중단 금지(8편).

**한 줄 요령:** **① 어느 쪽이 얼마나 이겼나(↑%) → ② 유의한가(p<0.05 / CI가 0 안 넘음 / Won) → ③ 안전한가(SRM·기간·가드레일).** 이 순서만 기억하면 어떤 A/B 결과표든 읽고 결정할 수 있습니다.

## 프레임워크에서 어디에 쓰이나

이 세 가지는 실무용 A/B 프레임워크의 **결과 신뢰성 계층**을 이룹니다. 성숙한 프레임워크(GrowthBook 등)는 실험 결과 화면을 열면 가장 먼저 **SRM 체크 배지**를 보여 줘서, 배정이 깨진 실험은 빨간 경고와 함께 결과 해석을 막습니다. 여러 지표·여러 변형을 한 화면에 놓을 때는 **다중비교 보정**을 옵션으로 적용하고, 지표마다 "핵심 / 가드레일" 역할을 지정해 가드레일이 무너지면 승자 배지를 띄우지 않습니다. 우리가 프레임워크를 밑바닥부터 만든다면, 분석 파이프라인을 `SRM 체크 → (통과 시) 지표별 검정 → 다중비교 보정 → 가드레일 검사 → 최종 판정` 순서의 관문으로 설계하는 게 자연스럽습니다.

## 한 줄 정리

지표를 여럿 보면 보정(본페로니·FDR)으로 우연 승자를 걸러내고, 분석 전에 SRM(카이제곱)으로 배정이 깨졌는지 먼저 확인하며, 가드레일 지표로 이기려다 다른 걸 망치지 않았는지 지키세요.
