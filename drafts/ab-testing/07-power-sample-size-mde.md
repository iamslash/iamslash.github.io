# 7편. 실험을 설계하기 — 검정력·표본 크기·MDE

> 시리즈: 밑바닥부터 이해하는 A/B 테스트 통계
> 이 편에서 배우는 것: 실험을 시작하기 전에 "몇 명을, 며칠 동안" 모을지 정하는 법 — MDE·검정력·표본 크기의 관계와 계산.

지난 편에서 콩마켓 실험 결과(22,000명씩, p≈0.005)를 계산했습니다. 그런데 이 실험은 **아무렇게나 2주간 돌린 게 아닙니다.** 시작 전에 이미 "arm당 약 22,000명, 대략 2주"라고 규모가 정해져 있었습니다. 그 숫자는 대체 어디서 나온 걸까요? 이번 편이 그 설계 계산입니다.

## 왜 시작 전에 규모를 정해야 하나

실험을 켜 놓고 결과를 계속 들여다보다가 "어, p<0.05 됐다! 멈추자" 하고 싶은 유혹이 생깁니다. 이걸 **훔쳐보기(peeking)**라고 하는데, 이렇게 하면 우연히 잠깐 유의해진 순간에 멈춰 **가짜 승자**를 뽑게 됩니다(자세한 함정은 다음 8편에서). 이 함정을 피하는 가장 확실한 방법은, **실험 전에 "표본 크기 N명을 채우면 멈춘다"를 못 박아 두는 것**입니다. 그래서 설계 계산이 먼저입니다.

설계에는 네 개의 손잡이가 있습니다: **MDE, 검정력, 유의수준 α, 표본 크기**. 이 중 세 개를 정하면 나머지 하나가 자동으로 결정됩니다.

## MDE — "이 정도는 좋아져야 의미 있다"

**MDE(minimum detectable effect, 최소 탐지 효과)** — 한마디로 "이 정도는 좋아져야 도입할 가치가 있다"고 미리 긋는 개선 기준선입니다. 실무에서는 비즈니스가 의미 있다고 보는 최소 효과를 목표 효과로 정하고, 그 효과를 목표 검정력으로 검출하도록 표본을 설계합니다. 표본 크기가 고정된 뒤에는 그 검정력을 달성하는 최소 효과를 MDE라고 부릅니다([GrowthBook 검정력 문서](https://docs.growthbook.io/statistics/power)).

여기서 헷갈리기 쉬운데, MDE는 "실제로 얼마나 개선될지"를 예측하는 게 아닙니다. **"실무적으로 의미 있는 최소 개선선"을 우리가 정하는 것**입니다. 조금 더 정확히 정리하면, 먼저 비즈니스가 의미 있다고 보는 최소 효과를 설계 목표로 정할 수 있습니다. 그 목표와 통계적 MDE가 일치하도록 표본을 설계하는 게 보통이지만, MDE 자체는 주어진 α·검정력·표본 크기에서 검출 가능한 최소 효과입니다. 왜 이게 필요할까요? 표본만 무한히 늘리면 0.001%p 같은 티끌 차이도 통계적으로 유의하게 만들 수 있습니다. 하지만 그런 차이는 버튼 색을 바꾸고 배포하는 수고를 들일 값어치가 없습니다. 그래서 "이 선 넘게 좋아지면 채택할 만하다"는 기준을 먼저 긋는 겁니다.

콩마켓은 이렇게 정했습니다.

> 전환율이 기존 5.0%에서 최소 **0.6%p**(상대 **+12%**), 즉 5.6%까지는 올라야 초록 버튼을 도입할 가치가 있다. → **MDE = 0.6%p**

MDE를 **작게** 잡을수록(더 미세한 차이까지 잡고 싶을수록) 필요한 표본은 급격히 늘어납니다. 이게 뒤에서 핵심입니다.

## 검정력 — "진짜 차이를 놓치지 않을 확률"

5편에서 **2종 오류(Type II error) — 진짜로 MDE만큼의 효과가 있는데도 결과가 유의하지 않아 그 효과를 발견하지 못하는 것**을 배웠습니다. 그 확률을 β라고 했습니다.

**검정력(statistical power) — 진짜로 MDE만큼의 차이가 있을 때, 그걸 실제로 "유의하다"고 잡아낼 확률**이고, 정의상 **power = 1 − β**입니다.

레이더에 비유하면, 검정력은 "진짜 비행기가 떠 있을 때 그걸 화면에 띄울 확률"입니다. 검정력 80%는 "진짜 MDE 차이가 있어도 5번 중 1번은 놓친다"는 뜻입니다. 업계 관행상 **80%**를 기본, 더 확실히 하고 싶으면 **90%**를 씁니다.

정리하면 우리는 두 가지 실수 확률을 각각 통제합니다.

- **α(유의수준)** = 효과가 없는데 있다고 착각할 확률(1종 오류). 보통 5%.
- **β = 1 − 검정력** = 효과가 있는데 놓칠 확률(2종 오류). 보통 20%(검정력 80%).

## 표본 크기 — 콩마켓은 왜 22,000명인가

이제 계산합니다. "기준 전환율(baseline) 5.0%에서 MDE 0.6%p 차이를, α=0.05·검정력 80%로 잡으려면 그룹 하나(arm)당 몇 명이 필요한가?"

비율 비교의 표본 크기 공식은 이렇게 생겼습니다(6편의 z-test를 뒤집어 유도한 것입니다). 1.96과 0.84는 정규분포 자의 눈금이며 외울 필요 없습니다.

```
n = ( z_(1−α/2)·√(2·p̄·(1−p̄)) + z_(1−β)·√(p1(1−p1)+p2(1−p2)) )² / (p2 − p1)²
```

- p1 = 0.050(대조군), p2 = 0.056(대조군 + MDE), p̄ = 두 값의 평균
- z_(1−α/2) = 양측 α=0.05에 대응하는 양의 임계값 ≈ 1.96
- z_(1−β) = 검정력 80%에 대응하는 값 ≈ 0.84
- 분자에서 1.96과 0.84를 함께 더하는 건 "가짜 승자를 막을 여유(1.96)"와 "진짜를 놓치지 않을 여유(0.84)"를 둘 다 확보해야 하기 때문입니다.

숫자를 넣으면 arm당 약 **21,885명**이 나옵니다. 실제로 p1=0.050, p2=0.056, p̄=0.053을 대입하면 n≈21,884.55가 나오고, 사람 수라 올림해 21,885명이 됩니다. 그래서 콩마켓은 여유를 살짝 얹어 **arm당 22,000명(≈2주 트래픽)**으로 설계한 겁니다. 검정력 80%를 확실히 채우고도 조금 남는 규모입니다. 만약 검정력을 90%로 올리고 싶었다면 **arm당 29,297명**, 대략 3주가 필요했을 겁니다.

### 코드: 표본 크기 계산기 (표준 라이브러리만)

```python
import math
from statistics import NormalDist   # Python 3.8+ 표준 라이브러리

N = NormalDist()  # 표준정규분포

def required_n(baseline, mde, alpha=0.05, power=0.80):
    """arm당(그룹 하나당) 필요한 표본 수. baseline=기준 전환율, mde=최소 탐지 효과.
    mde는 비율 단위로 입력한다(0.006 = 0.6%p)."""
    p1, p2 = baseline, baseline + mde
    z_alpha = N.inv_cdf(1 - alpha/2)   # 양측이라 α를 반으로. inv_cdf는 확률→정규분포 눈금값으로 되돌리는 함수
    z_beta  = N.inv_cdf(power)         # 검정력에 대응하는 값
    pbar = (p1 + p2) / 2
    num = (z_alpha*math.sqrt(2*pbar*(1-pbar))
           + z_beta*math.sqrt(p1*(1-p1) + p2*(1-p2)))**2
    return math.ceil(num / (mde**2))

print(required_n(0.05, 0.006, power=0.80))  # 21885
print(required_n(0.05, 0.006, power=0.90))  # 29297
```

`statistics.NormalDist`는 표준 라이브러리라 별도 설치가 필요 없습니다. scipy가 있다면 `scipy.stats.norm.ppf(1-alpha/2)`로 같은 값을 얻을 수 있고, 검정력 계산에 특화된 `statsmodels.stats.power`도 있습니다.

## 네 손잡이는 서로 묶여 있다

α·검정력·표본 크기·MDE는 하나를 조이면 다른 게 늘어나는 **트레이드오프** 관계입니다.

- **MDE를 작게** 하면(더 미세한 차이까지 잡고 싶으면) → 필요한 표본이 급증.
- **검정력을 높이면**(놓칠 확률을 줄이면) → 표본 증가.
- **α를 낮추면**(오탐을 더 엄격히 막으면) → 표본 증가.
- **표본이 고정**돼 있으면(트래픽이 한정적이면) → 잡을 수 있는 MDE가 커짐(= 큰 차이만 감지 가능).

MDE가 표본에 얼마나 강하게 영향을 주는지 봅시다. baseline 5%, α=0.05, 검정력 80% 고정입니다.

| MDE | (상대) | arm당 필요 표본 |
|---|---|---|
| 0.3%p | +6% | 85,199 |
| 0.6%p | +12% | 21,885 |
| 1.0%p | +20% | 8,158 |

MDE를 절반(0.6→0.3%p)으로 줄이면 표본은 약 **4배**로 뜁니다. "더 작은 차이까지 잡으려는 욕심"의 대가가 이렇게 큽니다. 트래픽이 부족한 서비스라면, 감지하려는 MDE를 현실적으로 키우는 게 답일 때가 많습니다.

### 코드: 검정력 곡선 그리기

표본 크기를 바꿔 가며 검정력이 어떻게 오르는지 보는 함수입니다.

이 함수 속 수식은 6편 z-test를 거꾸로 돌린 것이라 유도까지 이해할 필요는 없습니다. 하나만 챙기세요. n이 커지면 잡음 se0·se1이 작아지고 그만큼 검정력이 올라갑니다. 아래 출력 숫자가 그걸 보여줍니다.

```python
def power_at(baseline, mde, n, alpha=0.05):
    """arm당 n명일 때의 검정력."""
    p1, p2 = baseline, baseline + mde
    z_alpha = N.inv_cdf(1 - alpha/2)
    pbar = (p1 + p2) / 2
    se0 = math.sqrt(2*pbar*(1-pbar)/n)             # 귀무가설 하의 잡음
    se1 = math.sqrt((p1*(1-p1) + p2*(1-p2))/n)     # 대립가설 하의 잡음
    upper = N.cdf((mde - z_alpha * se0) / se1)     # 양의 방향 꼬리
    lower = N.cdf((-mde - z_alpha * se0) / se1)    # 음의 방향 꼬리(양측이라 더함)
    return upper + lower

for n in [5000, 10000, 15000, 22000, 29297, 40000]:
    print(f"n={n:>6,} -> power {power_at(0.05, 0.006, n)*100:4.1f}%")
```

출력(콩마켓 MDE 0.6%p 기준):

```
n= 5,000 -> power 26.8%
n=10,000 -> power 47.4%
n=15,000 -> power 64.0%
n=22,000 -> power 80.2%   ← 콩마켓 설계점
n=29,297 -> power 90.0%
n=40,000 -> power 96.6%
```

곡선을 눈으로 보면 실감 납니다. 표본이 5,000명일 땐 진짜 차이가 있어도 **4번 중 3번은 놓칩니다**(검정력 27%). 22,000명에서 80%에 도달하고, 그 뒤로는 표본을 아무리 부어도 검정력이 완만하게만 오릅니다(수확 체감). 그래서 무작정 오래 돌리기보다 "80~90% 검정력을 채우는 지점"에서 멈추도록 설계하는 겁니다.

> **핵심 감각 — "예측"이 아니라 "설계", 그리고 `1/√n` 형제들**
> - 검정력 계산은 **효과가 어떻게 될지 예측하는 게 아닙니다.** 진짜 효과는 (모르지만) 고정돼 있고, 이 계산은 **"표본이 쌓이면 내 실험의 탐지력이 어떻게 좋아지나"** 를 미리 그려보는 **설계 도구**입니다.
> - **표준오차(SE)·신뢰구간 폭·MDE·검정력은 전부 `1/√n` 한 뿌리에서 나오는 형제**입니다. 표본이 커지면 SE↓ → CI가 좁아짐 = MDE가 작아짐 = 검정력↑ 이 **동시에** 일어납니다(표본 4배면 SE·CI폭·MDE가 절반).
> - 그래서 표본을 미리 정해두면 두 실수를 막습니다: **① 훔쳐보기**(유의 뜨자 조기 중단 → 가짜 승자, 8편)와 **② 성급한 포기**(덜 모으고 "차이 없다" 결론 → 진짜 효과 놓침). 잘 설계된 실험은 **"유의 안 나옴"조차 믿을 수 있게** 만듭니다 — "의미 있는 효과가 있었다면 잡았을 것"이기 때문입니다.

## 프레임워크에서 어디에 쓰이나

GrowthBook 같은 프레임워크의 실험 생성 화면에 있는 "표본 크기 계산기 / 예상 소요 기간"이 바로 이 계산입니다. 사용자가 baseline 전환율, MDE, 원하는 검정력을 넣으면 프레임워크가 `required_n`과 똑같은 공식으로 arm당 필요한 방문자 수를 뽑고, 일일 트래픽으로 나눠 "며칠 걸린다"를 알려 줍니다. 이 목표 표본을 실험 메타데이터에 저장해 두면, 8편에서 볼 조기 종료(peeking) 방지와 순차 검정(sequential testing)의 기준선이 됩니다. 즉 이 편의 설계 계산이 "언제 실험을 멈춰도 되는가"를 정하는 출발점입니다.

## 한 줄 정리

실험은 시작 전에 "의미 있는 최소 효과(MDE)"와 "그걸 놓치지 않을 확률(검정력)"을 정해 필요한 표본 크기를 계산해 두어야 하며, 이 네 손잡이(MDE·검정력·α·표본)는 하나를 조이면 다른 게 늘어나는 트레이드오프입니다.
