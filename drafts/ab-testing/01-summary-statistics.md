# 1편. 데이터를 숫자 몇 개로 요약하기

> 시리즈: 밑바닥부터 이해하는 A/B 테스트 통계
> 이 편에서 배우는 것: 수천 명의 결제 데이터를 평균·중앙값·분위수·표준편차 같은 숫자 몇 개로 요약하는 법, 그리고 "잡음(출렁임)의 크기"를 재는 감각.

콩마켓 실험이 끝나고 데이터가 쌓였습니다. 초록 버튼(B)을 본 방문자 중 구매한 사람이 1,232명. 그런데 팀장님이 묻습니다. "그래서 초록 그룹 사람들, 한 명이 보통 얼마씩 쓴 거예요?"

구매자 1,232명의 결제액을 전부 나열해서 보여줄 수는 없습니다. 사람은 숫자 1,232개를 한눈에 이해하지 못합니다. 그래서 우리는 **많은 데이터를 대표하는 숫자 몇 개로 압축**합니다. 이게 기술통계(descriptive statistics)의 전부이고, 이번 편의 목표입니다.

설명을 손으로 따라갈 수 있게, 실제 1,232명 대신 그 축소판인 **10명짜리 미니 데이터셋**을 씁니다. 다음 값은 구매가 발생한 주문 10건의 금액을 설명용으로 뽑은 미니 데이터입니다(단위: 만원). 실제 A/B 보조 지표인 방문자당 매출은 비구매 방문자도 0원으로 포함하지만, 여기서는 요약 통계의 감을 잡기 위해 구매 건 10개만 떼어 봅니다.

```
[1, 1, 2, 2, 2, 3, 3, 4, 5, 12]
```

9명은 1~5만원짜리 원두를 샀는데, 한 명이 **12만원**짜리 스페셜 세트를 질렀습니다. 이 한 명이 앞으로 이야기의 주인공입니다.

## 평균 — 데이터의 무게중심

**평균(mean)** — 모든 값을 더해서 개수로 나눈 값. 데이터를 저울 위에 올렸을 때의 무게중심.

$$\text{평균} = \frac{1+1+2+2+2+3+3+4+5+12}{10} = \frac{35}{10} = 3.5$$

평균은 **3.5만원**입니다. 계산은 쉽습니다. 그런데 여기에 함정이 있습니다. 실제로는 10명 중 **7명이 평균(3.5만원)보다 적게** 썼습니다. 대부분의 사람이 평균 이하인데, 평균은 3.5만원이라니 좀 이상하죠?

범인은 12만원짜리 큰손 한 명입니다. 평균은 저울이라, 한쪽 끝에 유난히 무거운 값(이상치, outlier)이 하나 얹히면 무게중심이 그쪽으로 확 끌려갑니다. 평균은 이상치에 약합니다.

## 중앙값 — 딱 가운데 사람

**중앙값(median)** — 데이터를 크기순으로 줄 세웠을 때 정확히 한가운데 있는 값. 이상치에 흔들리지 않는 대표값.

우리 데이터는 이미 정렬돼 있고 10개(짝수)라 한가운데가 두 개입니다. 5번째와 6번째 값(2와 3)의 평균을 씁니다.

$$\text{중앙값} = \frac{2 + 3}{2} = 2.5$$

중앙값은 **2.5만원**입니다. "보통 사람은 2~3만원쯤 쓴다"는 우리의 체감과 훨씬 잘 맞습니다.

여기서 핵심 관찰: **평균(3.5) > 중앙값(2.5)**. 이렇게 평균이 중앙값보다 눈에 띄게 크면 "오른쪽 꼬리에 큰 값이 있다"는 신호입니다. 12만원짜리 큰손이 평균만 끌어올리고 중앙값은 못 건드린 거죠. 중앙값은 12만원을 그냥 "5번째보다 큰 어떤 값"으로만 취급하기 때문에, 그게 12든 120이든 꿈쩍하지 않습니다.

### 왜 핵심 지표로 중앙값을 쓰기도 하나

서비스의 성공을 대표하는 핵심 지표를 흔히 North Star Metric이라 부릅니다. 결제액이나 세션 시간처럼 **소수의 큰손이 오른쪽 꼬리를 길게 늘어뜨리는 지표**는, 평균을 이 핵심 지표로 잡으면 위험합니다. VIP 몇 명이 하루 결제를 크게 하면 평균이 출렁여서, 실제로 "보통 고객" 경험이 나빠졌는데도 평균은 좋아 보일 수 있으니까요. 그래서 이런 지표는 **중앙값(median)** 이나 뒤에 나올 분위수를 대표값으로 두는 경우가 많습니다. "우리 서비스의 전형적인 사용자"를 보고 싶기 때문입니다.

(참고: 콩마켓의 **핵심 지표는 전환율**이라 이 이슈에서 자유롭습니다. 결제액은 어디까지나 보조 지표예요. 하지만 결제액을 주요 지표로 볼 땐 이 함정을 꼭 기억하세요.)

## 분위수 / 백분위수 — 데이터를 등수로 자르기

평균 하나, 중앙값 하나로는 "꼬리"가 안 보입니다. 큰손이 얼마나 크게 쓰는지 보고 싶을 때 **분위수**를 씁니다.

**백분위수(percentile)** — 데이터를 크기순으로 세웠을 때 "아래에서 몇 %" 지점의 값. p90은 "하위 90% 지점의 값 = 상위 10% 손님이 넘어서는 문턱".

- **p50** = 하위 50% 지점 = 바로 **중앙값**입니다. (2.5만원)
- **p90** ≈ **5.7만원** — 손님 90%는 이보다 적게 씁니다. 상위 10% "단골"이 시작되는 문턱.
- **p99** — NumPy 선형보간으로 계산하면 **11.37만원**이 나오지만, 표본이 10개뿐이라 이 값을 실제 고객 **상위 1%**로 해석하면 안 됩니다. 최댓값 한 명(12만원)이 이미 표본의 10%를 차지하기 때문에, 상위 1%를 논하려면 훨씬 더 많은 데이터가 필요합니다. 이 미니 데이터셋에서는 p90 정도까지만 믿고 보세요.

p90, p99를 보면 데이터의 **꼬리 모양**이 보입니다. 서버 지연시간(latency)을 다뤄봤다면 익숙할 겁니다. 평균 응답시간이 아무리 좋아도 p99가 3초면 100명 중 1명은 3초를 기다린 거죠. 결제액도 똑같이, **데이터가 충분히 쌓이면** p99로 "우리 큰손들이 실제로 얼마나 크게 쓰나"를 볼 수 있습니다(방금 본 10명짜리 표본으로는 무리고요).

> 참고: 분위수는 데이터 사이 값을 어떻게 보간(interpolation)하느냐에 따라 라이브러리마다 조금씩 다르게 나옵니다. 위 p90=5.7, p99=11.4는 numpy의 기본(선형 보간) 기준입니다. 예컨대 p90은 8번째 값(5)과 9번째 값(12) 사이를 보간해 `5 + 0.1×(12−5) = 5.7`이 됩니다. 값이 딱 떨어지지 않아도 놀라지 마세요.

## 분산과 표준편차 — 출렁임의 크기

이제 이번 시리즈에서 **가장 중요한** 개념이 나옵니다. 앞의 평균·중앙값은 "데이터가 어디쯤 모여 있나(중심)"를 말합니다. 하지만 A/B 테스트에서 진짜 알고 싶은 건 **"데이터가 얼마나 흩어져 출렁이나(퍼짐)"** 입니다. 0편에서 말한 "잡음의 크기"가 바로 이겁니다.

왜 퍼짐이 중요할까요? 콩마켓 초록 그룹 평균이 3.5만원이라도, 다들 3~4만원에 옹기종기 모여 있는 것과, 1만원과 12만원이 뒤섞여 있는 것은 완전히 다른 상황입니다. 후자는 "다음에 표본을 다시 뽑으면 평균이 크게 흔들릴" 불안정한 데이터입니다. 이 흔들림의 크기를 재는 게 분산과 표준편차입니다.

**분산(variance)** — 각 값이 평균에서 얼마나 떨어졌는지(편차)를 제곱해서 평균 낸 값. "평균으로부터의 평균적인 거리"의 제곱.

편차를 그냥 더하면 +와 −가 상쇄돼 0이 됩니다(평균의 정의상 당연히요). 그래서 **제곱**해서 부호를 없앤 뒤 평균을 냅니다.

$$\text{분산} = \frac{\sum (x_i - \text{평균})^2}{n}$$

손으로 편차 제곱을 구해보면: 평균 3.5 기준으로
`(1-3.5)²=6.25`가 두 번, `(2-3.5)²=2.25`가 세 번, `(3-3.5)²=0.25`가 두 번, `(4-3.5)²=0.25`, `(5-3.5)²=2.25`, 그리고 큰손 `(12-3.5)²=72.25`.

다 더하면 94.5, 10으로 나누면 **분산 = 9.45**. 큰손의 72.25가 분산의 대부분을 차지하는 게 보이시죠? 이상치는 분산도 크게 부풀립니다.

그런데 분산은 단위가 "만원의 제곱"이라 감이 안 옵니다(9.45 제곱만원?). 그래서 제곱을 풀어 원래 단위로 되돌립니다.

**표준편차(standard deviation)** — 분산의 제곱근. "평균에서 보통 이만큼씩 떨어져 있다"를 원래 단위(만원)로 말해주는 값.

$$\text{표준편차} = \sqrt{9.45} \approx 3.07\text{만원}$$

표준편차 3.07만원은 결제액이 평균에서 떨어진 정도를 한 숫자로 요약한 크기입니다. 모든 결제액이 3.5±3.07만원 안에 있다는 뜻은 아닙니다. 표준편차가 클수록 데이터가 널뛰고, 작을수록 평균 근처에 얌전히 모여 있습니다. **이 "출렁임의 크기"가 앞으로 나올 표준오차·신뢰구간·p-value의 재료**가 됩니다. 잡음을 알아야 신호를 판단할 수 있으니까요.

### n으로 나누나, n−1로 나누나

표준편차 공식에서 마지막에 나누는 수가 두 가지입니다.

- **n으로 나누기 (모집단 공식):** 지금 가진 10명이 **전부**일 때. → 표준편차 **3.07**
- **n−1로 나누기 (표본 공식):** 이 10명이 더 큰 전체(모집단)에서 **뽑아온 표본**이고, 그걸로 전체의 퍼짐을 추정하려 할 때. → 표준편차 **3.24**

n−1로 나누면 값이 약간 커지는데(3.07 → 3.24), 왜 하필 n−1일까요? 편차는 **표본 평균**을 기준으로 재는데, 편차들의 합은 항상 0이 되어야 합니다. 그래서 앞의 n−1개 편차가 정해지면 마지막 하나는 자동으로 결정됩니다. 즉 독립적으로 움직일 수 있는 정보가 n−1개뿐인데, 이걸 **자유도(degrees of freedom)** 라고 부릅니다.

예를 들어 숫자가 딱 3개인데 평균이 5라고 합시다. 앞 두 개를 4, 6으로 내 맘대로 정하면 세 번째는 평균 5를 맞추려 반드시 5여야 합니다. 값이 3개여도 자유롭게 고를 수 있는 건 2개뿐 — 이 "2"가 자유도입니다. 그래서 표본 퍼짐은 n−1로 나눕니다.

이렇게 나누는 수를 바꾸는 건 편향을 바로잡기 위해서입니다. n으로 나눈 분산은 평균적으로 실제보다 조금 **작게** 나오는데, n−1로 나누면 **표본분산이 모집단 분산을 평균적으로 정확히 추정**하게 됩니다(이걸 불편추정량, unbiased estimator이라고 합니다). A/B 테스트에서는 22,000명이 전체 고객의 **표본**이므로 보통 **n−1(표본 공식)** 을 씁니다. n이 수만이면 n과 n−1 차이는 무시할 만큼 작아집니다. (엄밀히 이 보정은 분산 기준이라 표준편차에는 아주 작은 편향이 남지만, 실무에서 신경 쓸 수준은 아닙니다.)

## Python으로 확인하기

손계산이 맞는지 코드로 검증해봅니다. 먼저 표준 라이브러리 `statistics`만으로.

```python
import statistics as st

data = [1, 1, 2, 2, 2, 3, 3, 4, 5, 12]  # 만원

print(st.mean(data))       # 3.5   평균
print(st.median(data))     # 2.5   중앙값
print(st.pvariance(data))  # 9.45  분산 (모집단, n)
print(st.variance(data))   # 10.5  분산 (표본, n-1)
print(st.pstdev(data))     # 3.0741...  표준편차 (모집단, n)
print(st.stdev(data))      # 3.2404...  표준편차 (표본, n-1)
```

분위수와 백분위수는 numpy가 편합니다.

```python
import numpy as np

data = [1, 1, 2, 2, 2, 3, 3, 4, 5, 12]

print(np.percentile(data, 50))  # 2.5   = 중앙값
print(np.percentile(data, 90))  # 5.7   상위 10% 문턱
print(np.percentile(data, 99))  # 11.37 (표본 10개라 상위 1% 해석은 금물)

print(np.std(data))          # 3.0741...  n
print(np.std(data, ddof=1))  # 3.2404...  n-1 (ddof=1)
```

출력이 손계산과 정확히 맞습니다. `ddof=1`(delta degrees of freedom)이 바로 "n−1로 나누기" 스위치입니다.

## 전환율도 사실은 평균입니다

마지막으로 다음 편들과 이어지는 다리를 하나 놓겠습니다. 지금까지 결제액(연속형 숫자)으로 평균을 이야기했는데, 콩마켓의 **핵심 지표인 전환율도 사실 평균**입니다.

방문자 한 명 한 명에게 "샀으면 1, 안 샀으면 0"을 붙여봅니다. 초록 그룹 22,000명이 이런 0/1 목록이 됩니다.

```
[0, 0, 1, 0, 0, 0, ..., 1, 0]   # 22,000개, 이 중 1이 1,232개
```

이 0과 1을 전부 더하면 구매자 수(1,232), 개수로 나누면?

$$\frac{1{,}232}{22{,}000} = 0.056 = 5.6\%$$

**전환율 5.6% = 0/1 값들의 평균**입니다. 즉 전환율은 "이진(binary) 데이터의 평균"일 뿐이에요. 그래서 이번 편에서 배운 평균·분산·표준편차가 전환율에도 그대로 적용됩니다. 0과 1로만 이뤄진 데이터도 나름의 표준편차(출렁임)를 가지며, 그게 다음 편들에서 "전환율 5.6%가 얼마나 믿을 만한가"를 따지는 출발점이 됩니다. 참고로 0과 1만 있는 데이터의 표준편차는 전환율 p로 √(p(1−p))처럼 나오는데(3편에서 씁니다), 지금은 "0/1 데이터도 퍼짐이 있다"만 기억하세요.

## 프레임워크에서 어디에 쓰이나

A/B 테스트 프레임워크의 **집계(aggregation) 계층**이 하는 일이 정확히 이번 편의 내용입니다. GrowthBook 같은 도구는 데이터 웨어하우스에서 실험군별로 이벤트를 긁어와, 각 지표의 **합(sum)·개수(count)·평균(mean)·분산(variance)** 을 계산해 저장합니다. 특히 분산은 그냥 참고용이 아니라 뒤에 나올 신뢰구간과 p-value 계산에 **반드시 필요한 입력값**이라, 프레임워크는 지표마다 분산을 꼭 함께 집계해 둡니다. 또한 결제액처럼 꼬리가 긴 지표에는 이상치가 분산을 터뜨리지 않도록 **윈저화(winsorization, 극단값을 p99 같은 문턱으로 잘라내기)** 옵션을 제공하는데, 그 문턱을 정하는 게 바로 이번 편의 분위수입니다. 요약 통계는 통계 엔진에 들어가는 원재료인 셈입니다.

## 한 줄 정리

평균은 중심, 중앙값·분위수는 이상치에 흔들리지 않는 중심과 꼬리, 표준편차는 **"데이터가 얼마나 출렁이는가(잡음의 크기)"** 를 재며, 이 출렁임이 앞으로 A/B 판정의 핵심 재료가 됩니다.
