# 6편. p-value를 실제로 계산하기 — z-test와 t-test

> 시리즈: 밑바닥부터 이해하는 A/B 테스트 통계
> 이 편에서 배우는 것: 콩마켓 실험 결과에서 p-value를 손으로, 그리고 코드로 실제 계산하는 두 가지 레시피(z-test, t-test).

지난 편까지 우리는 p-value가 "귀무가설(효과가 없다)이 사실일 때, 지금 본 것만큼 극단적인 차이가 우연히 나올 확률"이라는 걸 배웠습니다. 개념은 잡혔는데, 정작 **그 숫자를 어떻게 뽑는지**는 아직 안 배웠습니다. 이번 편이 바로 그 계산 레시피입니다.

콩마켓 실험이 2주간 돌아 결과가 나왔다고 합시다.

| | 방문 | 구매 | 전환율 |
|---|---|---|---|
| A(파랑) | 22,000 | 1,100 | 5.00% |
| B(초록) | 22,000 | 1,232 | 5.60% |

초록 버튼이 0.6%p 높습니다. "이게 진짜 효과냐, 아니면 그냥 운이냐?"에 답하는 숫자, p-value를 이제 실제로 계산해 봅니다.

---

## 도구는 두 개: z-test와 t-test

가설검정의 계산은 늘 같은 모양입니다.

```
검정통계량 = 신호 / 잡음 = (관측된 차이) / (그 차이의 표준오차)
```

**표준오차(standard error) — 표본에서 계산한 값이 순전히 운 때문에 얼마나 출렁이는지의 크기**입니다. 차이가 잡음(표준오차)의 몇 배냐를 재는 게 검정통계량이고, 그 배수가 클수록 "우연이라기엔 너무 크다 → 유의하다"가 됩니다.

이 배수를 어떤 분포에 대고 확률로 바꾸느냐에 따라 도구가 갈립니다.

- **z-test** — 배수를 정규분포(종모양)에 댑니다. **비율(전환율)**이나 **표본이 큰** 경우에 씁니다.
- **t-test** — 배수를 t분포에 댑니다. **평균**을 비교하는데 **표본이 작거나** 데이터의 흩어짐(분산)을 모를 때 씁니다.

콩마켓 전환율은 비율 + 표본 44,000명으로 아주 큽니다. 그래서 z-test가 딱 맞습니다.

---

## z-test로 콩마켓 전환율 검정하기 (손계산)

전환율처럼 "구매/비구매" 두 값만 있는 지표를 **이진 지표(binary metric)**라고 합니다. 두 그룹의 비율을 비교하는 건 **2-표본 비율 z-test(two-sample proportion z-test)**입니다.

**1단계 — 두 전환율.**
p_A = 1100 / 22000 = 0.0500, p_B = 1232 / 22000 = 0.0560. 관측된 차이는 0.0060(0.6%p)입니다.

**2단계 — pooled 비율.**
귀무가설은 "A와 B의 진짜 전환율이 같다"입니다. 같다고 가정하니, 잡음을 계산할 때도 두 그룹을 **하나로 합친(pooled)** 비율을 씁니다.

```
p̄ = (구매 합) / (방문 합) = (1100 + 1232) / (22000 + 22000) = 2332 / 44000 = 0.0530
```

**3단계 — 표준오차(잡음).**
비율의 표준오차 공식은 √(p̄(1−p̄)(1/n_A + 1/n_B))입니다. "성공/실패 비율이 반반에 가까울수록, 표본이 작을수록 잡음이 크다"는 걸 담은 식입니다.

```
SE_pool = √(0.0530 × 0.9470 × (1/22000 + 1/22000)) = 0.002136
```

**4단계 — z값(신호/잡음).**

```
z = (p_B − p_A) / SE_pool = 0.0060 / 0.002136 = 2.81
```

관측된 차이가 잡음의 **2.81배**라는 뜻입니다.

**5단계 — z를 p-value로.**
z=2.81을 정규분포에 대고, "우연히 이만큼(양쪽 방향 모두) 벗어날 넓이"를 읽습니다. 한 단계씩 보면 이렇습니다. z=+2.81보다 오른쪽 넓이는 약 0.2485%입니다. 양측 검정은 −2.81보다 왼쪽 꼬리도 함께 세므로 0.2485%×2=0.497%, 즉 **양측 p-value = 0.00497**(≈0.005)입니다. 유의수준 α=0.05보다 작으니 **통계적으로 유의**합니다. (아래 코드의 `sf`는 오른쪽 꼬리 넓이를 돌려주는 survival function입니다.)

### 코드로 확인 (표준 라이브러리만)

```python
import math

def norm_sf(z):
    # 표준정규분포의 오른쪽 꼬리 넓이 P(Z > z).
    # erfc는 정규분포 꼬리 넓이를 정확히 계산하는 표준 라이브러리 내장 함수 —
    # 내용은 몰라도 되고 결과만 씁니다.
    return 0.5 * math.erfc(z / math.sqrt(2))

nA, nB = 22000, 22000
xA, xB = 1100, 1232              # 각 그룹의 구매 수
pA, pB = xA / nA, xB / nB        # 0.050, 0.056

pbar = (xA + xB) / (nA + nB)     # pooled 비율
se_pool = math.sqrt(pbar * (1 - pbar) * (1/nA + 1/nB))
z = (pB - pA) / se_pool
p_two = 2 * norm_sf(abs(z))      # 양측 p-value

print(f"pooled p̄ = {pbar:.4f}")   # 0.0530
print(f"SE_pool  = {se_pool:.6f}") # 0.002136
print(f"z        = {z:.2f}")       # 2.81
print(f"양측 p   = {p_two:.5f}")   # 0.00497
```

**scipy/statsmodels가 있다면** 한 줄로 같은 값을 얻습니다.

```python
from statsmodels.stats.proportion import proportions_ztest
z, p = proportions_ztest([1232, 1100], [22000, 22000])  # z≈2.81, p≈0.005
```

(`proportions_ztest`는 statsmodels 패키지에 있습니다. 설치가 안 돼 있으면 위의 표준 라이브러리 버전이 그대로 폴백입니다.)

## 양측 vs 단측, 뭐가 다른가

- **양측 검정(two-sided)** — "A와 B가 **다르다**"만 묻습니다. 초록이 더 좋을 수도, 더 나쁠 수도 있으니 양쪽 꼬리를 모두 셉니다.
- **단측 검정(one-sided)** — "초록이 파랑보다 **더 좋다**"처럼 방향을 미리 못 박고 한쪽 꼬리만 셉니다. 관측 z가 사전에 정한 방향과 같을 때 단측 p는 양측 p의 절반이 되어 유의가 더 쉽게 나오지만, 반대 방향이면 단측 p는 오히려 매우 커집니다. 게다가 "혹시 더 나빠질 위험"을 아예 안 보는 셈입니다.

실무 A/B 테스트는 거의 항상 **양측**을 기본으로 씁니다. 새 디자인이 오히려 전환율을 떨어뜨리는 경우도 실제로 자주 있어서, 그 위험을 검정에서 빼면 안 되기 때문입니다. 콩마켓도 양측으로 p≈0.005를 보고합니다.

## t-test: 평균을 비교할 때 (작은 표본)

전환율 말고 **인당 결제액**처럼 연속형(continuous) 지표의 평균을 비교하고 싶을 때가 있습니다. 예를 들어 초록 버튼이 "더 비싼 상품까지 사게 만드는가?"를 보려면 구매자 1인당 결제액의 평균을 A와 B에서 비교합니다.

문제는, 실험 초반이거나 특정 세그먼트만 떼어 보면 **구매자 수가 몇 명 안 될 때**가 있다는 겁니다. 이럴 때 z-test를 쓰면 안 됩니다. 이유는 두 가지입니다.

1. **진짜 분산을 모릅니다.** 비율은 p̄만 알면 잡음이 자동으로 정해졌지만, 결제액의 흩어짐은 표본에서 **추정**해야 합니다. 표본이 작으면 이 추정 자체가 불안합니다.
2. 그 불안함을 정규분포는 반영하지 못합니다.

그래서 **t분포(t-distribution)**를 씁니다. t분포는 종모양이지만 **꼬리가 더 두껍습니다**. "표본이 작아서 우리가 잡음을 과소평가했을 수도 있다"는 불확실성을 꼬리를 두껍게 만들어 반영해 주는 겁니다. 표본이 커질수록 꼬리가 얇아지며 정규분포에 가까워집니다.

t분포의 두께를 정하는 게 **자유도(degrees of freedom, df)**입니다. 대략 "표본 크기에서 몇을 뺀 값"으로, 데이터가 많을수록(df가 클수록) 정규분포에 수렴합니다. df가 작을수록 꼬리가 두껍고, 같은 t값이라도 p-value가 더 큽니다(= 더 보수적). 왜 "몇을 뺀 값"일까요? 한 그룹에서 평균 하나를 추정하면 n−1개의 편차만 자유롭게 움직입니다(마지막 하나는 평균에 맞춰 자동으로 정해집니다). Welch 검정은 두 그룹의 표본 크기와 분산을 합쳐 유효 자유도를 계산합니다.

### 콩마켓 예제: 인당 결제액 (초반 데이터, 각 6명)

> 참고: 이 6명짜리 예제는 **Welch 계산을 손으로 보여주기 위한 별도의 구매액 미니 예제**입니다. 이 시리즈의 보조 지표는 사실 **방문자당 매출**(구매하지 않은 방문자는 0원으로 포함)입니다. 여기처럼 비구매자를 빼고 구매자만 놓고 평균을 비교하면 "구매 여부 자체가 바뀌는 효과"를 놓치는 조건부 비교의 한계가 있습니다. 지금은 t-test 손계산 절차만 익힌다고 보시면 됩니다.

실험 첫날, 파랑/초록에서 각각 6명이 구매했고 결제액(만원)이 이렇게 나왔다고 합시다.

```
A(파랑): [3.2, 2.9, 3.5, 2.7, 3.0, 2.7]   평균 3.0만원
B(초록): [3.9, 3.6, 4.3, 3.4, 3.8, 3.2]   평균 3.7만원
```

두 그룹의 분산이 다를 수 있으니, 실무 기본값인 **Welch t-test**(분산이 같다고 가정하지 않는 버전)로 계산합니다.

```python
import math

def mean(v): return sum(v) / len(v)
def var(v):                                  # 표본분산(n-1로 나눔)
    m = mean(v); return sum((x-m)**2 for x in v) / (len(v)-1)

A = [3.2, 2.9, 3.5, 2.7, 3.0, 2.7]
B = [3.9, 3.6, 4.3, 3.4, 3.8, 3.2]
nA, nB = len(A), len(B)

se = math.sqrt(var(A)/nA + var(B)/nB)        # 두 평균 차이의 표준오차
t  = (mean(B) - mean(A)) / se
# 아래 df 공식은 외우지 마세요. scipy가 대신 계산합니다.
df = (var(A)/nA + var(B)/nB)**2 / (          # Welch 자유도
     (var(A)/nA)**2/(nA-1) + (var(B)/nB)**2/(nB-1))

print(f"평균 A={mean(A):.1f}, B={mean(B):.1f}")  # 3.0, 3.7
print(f"SE = {se:.4f}")                          # 0.2033
print(f"t  = {t:.2f},  df = {df:.1f}")           # t=3.44, df=9.5
```

t = 3.44가 나왔습니다. 이제 이걸 **t분포(df=9.5)**에 대고 p-value를 읽어야 합니다. t분포 꼬리 확률 구현은 수치해석 영역이라 검증된 라이브러리를 쓰는 게 맞고, 프레임워크에서도 그렇게 합니다. scipy로 두 줄이면 됩니다.

```python
from scipy import stats

p_two = 2 * stats.t.sf(abs(t), df)   # t분포의 양쪽 꼬리 넓이 → 양측 p
print(f"양측 p = {p_two:.4f}")        # 0.0068

# 평균 비교라면 한 줄짜리 함수로도 같은 값을 얻습니다.
t_val, p_val = stats.ttest_ind(B, A, equal_var=False)   # Welch, p ≈ 0.0068
```

**핵심 포인트:** 같은 t=3.44라도 잘못 정규분포(z)에 대면 p ≈ 0.0006이 나옵니다. 반면 올바른 t분포(df=9.5)에 대면 p ≈ 0.0068로, **약 10배** 큽니다. 표본이 작을 때 z를 쓰면 이렇게 p-value가 실제보다 훨씬 작게 나와 "유의하다"고 과신하게 됩니다. 그래서 Welch t-test는 두 그룹이 독립이고 각 그룹 데이터가 대략 정규적일 때 작은 표본에서도 쓸 수 있습니다. 결제액이 심하게 치우치고 n=6이라면 로그변환, permutation test, bootstrap, 또는 더 큰 표본을 검토해야 합니다. (이 예제는 결과가 여전히 유의하지만, 경계선 근처였다면 z/t 선택이 결론을 바꿉니다.)

## z냐 t냐, 한눈에

| | z-test | t-test |
|---|---|---|
| 주로 쓰는 지표 | 비율(전환율) | 평균(결제액 등) |
| 표본 크기 | 큼 | 작아도 됨 |
| 분산(흩어짐) | 알거나 자동 결정 | 표본에서 추정 |
| 대는 분포 | 정규분포 | t분포(꼬리 두꺼움, df) |
| 콩마켓 적용 | 전환율 5.0% vs 5.6% | 인당 결제액 초반 비교 |

실무에선 표본이 크면 t분포가 정규분포와 거의 같아지므로, 평균 비교라도 표본만 크면 z와 t의 답이 사실상 같아집니다. 그래도 "평균이면 t, 비율이면 z"로 습관 들이면 안전합니다.

## 프레임워크에서 어디에 쓰이나

GrowthBook 같은 A/B 프레임워크의 "결과(Results)" 화면에서 각 지표 옆에 뜨는 p-value가 바로 이 계산의 산물입니다. 다만 이 글의 proportion z-test는 원리 학습용 구현입니다. 현재 GrowthBook은 공통 효과·표준오차 계층 위에서 Welch t 추론을 쓰며, 큰 이진 표본에서는 여기 z-test와 사실상 같은 값이 됩니다([GrowthBook 통계 상세](https://docs.growthbook.io/statistics/details)). 우리가 방금 손으로 짠 `se_pool`, `z`, `t`, `df` 계산이 그 엔진의 심장부입니다. 다음 편에서 볼 검정력·표본 크기 계산도 결국 이 z/t 통계량을 뒤집어 유도합니다.

---

## 한 줄 정리

p-value는 "(관측된 차이) ÷ (표준오차)"로 검정통계량을 만든 뒤 그 값을 분포에 대어 읽는 것이고, 비율·큰 표본이면 정규분포의 z-test, 평균·작은 표본이면 꼬리가 두꺼운 t분포의 t-test를 씁니다.
